# 예외 유형 카탈로그 — 추가 작업(`예외 사항`) 전용

`testcase-augment` 의 `예외 사항` 모드에서만 읽는다. 기획서 기반 생성(`testcase-auto`)에서는
읽지 않는다 — 그쪽의 `비정상`·`엣지` 케이스는 기획서에 근거가 있다.

**원천은 기존 테스트 케이스다.** 기획서를 읽지 않으므로 예상 결과의 확정값을 단정하지 않는다
(`common.md` 「파생 케이스의 원천」 규칙 4).

## 도출 대상은 범위 안의 원본 케이스뿐이다

Phase 0에서 **범위(화면 ID 목록)** 가 확정되고 인벤토리에 이미 적용돼 있다.
**인벤토리에 없는 화면은 사용자가 뺀 것이다** — 원본 탭에 있다는 이유로 끌어오지 않는다
(리뷰에서 범위 초과 Critical).

## 도출 축 — 원본 케이스별 뒤집기 + 카탈로그 점검

1. **뒤집기(주 경로)** — 원본 케이스 1건마다 *"이 절차가 실패하는 조건"* 을 도출한다 (1:N).
   `비고` 에 `[예외 파생 {원본 기능테스트 ID}] {예외 유형명}` 을 남겨 역추적을 보장한다
2. **카탈로그 점검(보조 경로)** — 뒤집기를 마친 뒤 아래 유형을 훑어 **적용 가능한데 0건인 유형**을
   찾는다. 만들지 않기로 판단했으면 **사유를 산출물에 적는다**

> 카탈로그는 **상한이 아니라 하한**이다. 카탈로그에 없는 예외를 발견하면 만들고
> **카탈로그 추가를 보고**한다.
> **단 아래 「제외 상황」 은 이 하한 규칙보다 우선한다.**

## 제외 상황 — 만들지 않는다 (하한 규칙보다 우선)

아래 5종은 **팀 지시로 예외 사항 TC에서 제외**한다. 뒤집기·카탈로그 점검·적용 판정
어느 경로로 도출됐든 만들지 않는다.

**제외 유형을 카탈로그 표에서 지우지 않고 남겨 둔 이유가 여기 있다** — 지우면 같은 상황이
*"카탈로그에 없는 새 예외"* 로 재발견되어 하한 규칙을 타고 그대로 되돌아온다.

| # | 제외 상황 | 덮는 유형 |
|---|-----------|----------|
| E1 | **조회 API 오류·조회 중 새로고침** — 목록 조회 API 오류, 페이지 조회 중인 상태에서 새로고침 시도 등 | 9 전체 · 12 |
| E2 | **일반적인 팝업 닫기** — 삭제 확인 팝업에서 취소 버튼 클릭 등 | 12 |
| E3 | **경계값** — 입력 범위 밖 값, 허용되지 않는 값 입력 | 3 · 5 |
| E4 | **기능과 관계 없는 브라우저 조작** — 팝업 외부 영역 클릭 후 ESC 입력, 입력 도중 브라우저 새로고침 등 | 12 |
| E5 | **반복 동시 조작** — 생성·삭제 버튼을 연속으로 빠르게 2회 클릭 등 | 10 일부 |

**E3 은 형식 유효성 검증을 제외하지 않는다.** `특수문자 입력 시 저장 차단` 같은 유형 2는
*허용 문자·패턴 위반* 이지 경계값이 아니다. 필수값 누락(1)·중복 값(4)도 그대로 유지한다.

**E5 는 유형 10 전체를 제외하지 않는다.** 한 사용자의 연속 클릭·중복 제출만 빠지고
**두 사용자 동시 수정**(동시 편집 충돌)은 남는다 — 성격이 다른 검증이다.

> **제외로 0건이 된 유형은 산출물에 사유를 적지 않는다.** 「카탈로그 미적용 사유」는
> *적용 가능한데 만들지 않은* 유형만 대상이며, 제외 유형의 사유는 이 표가 단일 출처다.

## 유형 카탈로그 — 8종 적용 · 4종 제외

번호는 **고정 식별자**다. 제외 유형의 번호를 회수해 재부여하지 않는다 — 번호가 밀리면
과거 산출물의 `유형 3` 이 다른 뜻이 된다.

| # | 유형 | 검증 지점 예 | 적용 |
|---|------|------------|------|
| 1 | 필수값 누락 | 필수 입력 비운 채 제출 | O |
| 2 | 형식 위반 | 허용 문자·패턴 위반 (특수문자·공백·한글) | O |
| 3 | 길이 경계 | 최소−1 / 최소 / 최대 / 최대+1 | **제외 (E3)** |
| 4 | 중복 값 | 이미 존재하는 이름·ID로 생성 | O |
| 5 | 범위 이탈 | 숫자·날짜 범위 밖, 음수, `0` | **제외 (E3)** |
| 6 | 존재하지 않는 대상 | 삭제된 리소스 재조회, URL 직접 진입 | O |
| 7 | 상태 전이 불가 | 실행 중 삭제, 완료 건 취소 | O |
| 8 | 권한·세션 | 세션 만료, 인증 소실, 타 조직 리소스 접근 | O |
| 9 | 서버·네트워크 오류 | 5xx, 타임아웃, 응답 지연 | **제외 (E1)** |
| 10 | 동시성 충돌 | 두 사용자 동시 수정 | **축소 (E5)** — 연속 클릭·중복 제출 제외 |
| 11 | 데이터 규모 경계 | 0건, 1건, 대량, 페이지 경계 | O |
| 12 | 중단·이탈 | 취소, 뒤로가기, 새로고침, 창 종료 | **제외 (E1·E2·E4)** |

## 적용 가능성 판정 — 전 유형을 전 기능에 적용하지 않는다

조회 전용 화면에 「필수값 누락」을 만들면 검증 목표가 없는 행이 된다.

| 원본 기능 단위의 성격 (`3 Depth` · 절차 동사) | 적용 유형 |
|---|---|
| 입력 폼 (`생성` · `수정`) | 1, 2, 4, 10 |
| 목록 조회 (`목록`) | 6, 8, 11 |
| 상세 · 팝업 (`상세`) | 6, 7, 8 |
| 삭제·실행 액션 | 6, 7, 8, 10 |
| **전 성격 공통** | **8** |

- **판정 근거는 원본 케이스의 `절차` 와 `3 Depth` 다.** 화면 성격을 유추하지 않는다
- 적용 유형인데 만들지 않았으면 **사유를 `12_cases_{EX|PM}-B{NN}.md` 에 적는다**
- 위 표는 **제외 반영 후의 값이다.** `전 성격 공통` 이 유형 8 하나인 것은 9·12가 제외된 결과이며
  누락이 아니다

## 중복 판정 — 이미 있는 검증 목표는 만들지 않는다

문자열 일치가 아니라 **검증 목표 일치**다. 판정 근거는 인벤토리의 **기존 커버리지 맵**이다.

| 상황 | 판정 |
|------|------|
| 원본에 `필수값 미입력 시 저장 차단` 이 있고 같은 것을 만듦 | **중복 — 만들지 않는다** |
| 원본에 `이름 필수값 미입력` 이 있고 `설명 필수값 미입력` 을 만듦 | 필드가 다르면 별개 검증 목표 — 만든다 |
| 원본 `구분` 이 `비정상` 이지만 내용은 다른 예외 | 만든다 |

중복으로 걸러낸 후보는 산출물의 「중복 제외」 절에 **원본 TC ID와 함께** 적는다.

## 양식 매핑

| 컬럼 | 값 |
|------|-----|
| `구분` | `비정상` 주력 / 데이터 규모 경계(유형 11) → `엣지` |
| `우선순위` | **프로파일의 구분 × 우선순위 결합 규칙을 따른다.** 여기 값을 박지 않는다 |
| `화면 ID` · `1 Depth` · `2 Depth` · `3 Depth` | **원본 케이스에서 승계.** 유추 금지 |
| `사전조건` | 예외 진입 조건 1줄 (프로파일이 100% 채움을 요구하면 반드시 채운다) |
| `절차` | `N. ` 접두 100%, 1단계 원칙 |
| `예상 결과` | **명사형 종결.** 동작 수준까지만 |
| `비고` | `[예외 파생 {원본 기능테스트 ID}] {예외 유형명}` |
| `피드백` | `[기획 확인] {무엇이 미정의인가} — 확정값 확인 필요` |

> **`구분` 은 `비정상`·`엣지` 두 값만 쓴다.** 경계값(유형 3·5)과 취소·비활성(유형 12)이
> 제외되면서 `부수` 를 낳던 경로가 사라졌다 — `common.md` 「파생 케이스 작성 규칙」 3이
> 선언한 *"예외 파생은 `비정상`·`엣지` 만"* 과 일치한다.

> **결합 규칙을 이 문서에 박지 않는 이유.** VIOLA는 `정상` 에 `P1`·`P2` 만 주고 `P3`·`P4` 사례가
> 0건인데 TROMBONE `정상` 은 `P1`~`P4` 를 전부 쓴다. 한쪽 값을 옮겨 적으면 2026-08-24 분포
> 하드코딩 사고(`정상` −44.9%p)를 형태만 바꿔 재현한다. **브리핑의 프로파일 절에서 읽어라.**

## 예상 결과를 어디까지 쓰는가

```
좋은 예: `필수 입력값 누락` 오류 메시지 표출 및 저장 차단
        → 동작(차단)은 단정, 문구는 성격까지만

나쁜 예: "이름을 입력해 주세요" 토스트 메시지 표출
        → 기획서에 없는 문구를 단정 → 실행자가 잘못된 FAIL을 낸다
```

**문구·코드·지연 시간 같은 확정값은 단정하지 않고 `[기획 확인]` 으로 넘긴다.**
예상 결과를 단정해 놓고 확인 불가를 적으면 실행자가 PASS/FAIL을 내려 버린다
(`common.md` 자기모순 금지).
