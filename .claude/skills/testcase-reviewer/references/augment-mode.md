# 추가 작업 모드 리뷰 — `testcase-augment` 산출물 전용

기획서가 없는 절차의 산출물을 리뷰한다. **「기획 ↔ 케이스」 경계면을
「원본 TC ↔ 파생 케이스」 경계면으로 대체**한다.

## 먼저 — 결정적 점검은 스크립트가 이미 했다

```bash
python scripts/verify_sheet_rows.py --profile={프로파일} --sheet=<대상> --tab='{탭}' --rows=<범위>
python scripts/verify_sheet_rows.py --profile={프로파일} --tsv=<13_rows_all_{EX|PM}.tsv> \
    --sheet=<대상> --tab='{탭}' --diff
```

헤더·23컬럼·`피드백` 뒤 열 오염·enum 3종·결합 규칙·`솔루션` 단일값·TC ID 형식·중복·
`No` 연속성·`-` vs 빈칸·`비고`/`사전조건` 공란·절차 `N. ` 접두·명사형 종결·본문 열 문체·
셀 내 파이프는 **전수 판정이 끝나 있다.** 같은 것을 눈으로 다시 세지 않는다.

**이 스크립트는 추가 작업용으로 수정되지 않았다.** `비고` 를 공란 여부로만 보고 태그 어휘를
검사하지 않으므로 파생 태그가 위반으로 잡히지 않는다.

## 점검 항목 (판단이 필요한 것만)

| 점검 | 판정 |
|------|------|
| 기능 단위 누락 — 1-C에서 확정한 대상에 파생분이 없는 것 | Major |
| **기존 케이스와 중복** — 같은 검증 목표가 이미 원본에 있는데 다시 만든 것 | Major |
| 예외 카탈로그 미적용 — 적용 가능 유형인데 케이스가 0건 | Minor (사유 기재 시 통과) |
| **(권한) 매트릭스 셀 ↔ 케이스 1:1** — 누락 셀 | **Critical** |
| **(권한) 매트릭스에 없는 조합을 만든 것** (범위 초과) | **Critical** |
| 승계 정확성 — `화면 ID`·`1~3 Depth` 가 원본과 일치하는가 | Major |
| `예상 결과` 단정 ↔ `[기획 확인]` 자기모순 | Major |
| 파생 태그 형식 (`[예외 파생 {원본 TC ID}]` 의 ID가 실재하는가) | Major |

- 「원본 TC ↔ 파생」 대조의 근거는 `10_tc_inventory.md` 의 **기능 단위 표와 커버리지 맵**이다
- 「매트릭스 셀 ↔ 케이스」 대조의 근거는 `11_permission_matrix.md` 다
- **작성자 자기 점검 서술을 인용하지 말고 독립 실측하라**

## ⚠️ 오판 방지 — 이 절차에서는 여러 기준이 정반대다

| 지적하면 오판인 것 | 이유 |
|---|---|
| **`구분` 분포가 프로파일과 다르다** | 예외는 `비정상`·`엣지` 만, 권한은 `정상`·`부수` 만 만드는 것이 이 작업의 정의다 |
| **`표시` 케이스가 없다 / 커버리지 부족** | 표시 검증은 기획서 기반 작업의 영역이다. 이 절차의 산출물이 아니다 |
| **기획서 근거 태그(`[DESC …]`)가 없다** | 원천이 기획서가 아니다. `[예외 파생 …]`·`[권한 매트릭스 …]` 가 정상 근거다 |
| **`예상 결과` 에 오류 문구가 없어 불충분하다** | 문구 단정 금지가 규칙이다. 문구를 적었다면 그쪽이 위반이다 |
| **`[기획 확인]` 이 너무 많다** | 기획 미정의 영역을 다루므로 대량 발생이 정상이다 |
| **TC ID가 원본과 이어지지 않는다 / 화면 블록이 흩어졌다** | append-only이므로 파생분은 대상 탭 끝에 붙는다. 원본 화면 블록과 떨어지는 것이 정상이다 |
| **미대응 기능이 누락됐다** | 1-C·Phase 4에서 제외를 명시하고 사용자가 확인한 항목이다 |
| **`No` 가 1부터 시작한다** | 신규 탭이면 `common.md` 대로 탭별 1부터 재시작이 맞다 |

**반대 방향도 함께 점검한다.** 위 목록은 **실제 결함을 통과시키라는 뜻이 아니다.**
예컨대 "분포 점검 제외"는 `구분` 값 자체가 enum 밖인 것을 통과시키라는 뜻이 아니다
(그건 `verify_sheet_rows.py` 가 잡는다).
