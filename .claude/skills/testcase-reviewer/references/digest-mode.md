# 기획서 분석 모드 리뷰 — `prd-digest` 산출물 전용

테스트 케이스가 없는 절차의 산출물을 리뷰한다. **「기획 ↔ 케이스」 경계면을
「기획서 ↔ 기능 목록」 경계면으로 대체**하고, 「양식 ↔ 케이스」·「로컬 ↔ 시트」 두 경계면은
**성립하지 않는다** — 이 절차는 양식 프로파일도 구글 시트도 쓰지 않는다.

리뷰 대상은 탭이 아니라 `{WS}` 산출물 전체다 — 화면별 `02_screen_s{NN}.md` ·
`02_features_s{NN}.tsv` 와 렌더 결과 `03_기능_전체.md` · `04_신규변경.md`.

## 먼저 — 결정적 점검은 스크립트가 이미 했다

```bash
python scripts/verify_digest.py --ws={WS} --pages=<총 페이지 수>
```

TSV 열 수(`TSV_COLS`) · 분류 enum(`CLASS_ENUM`) · `신규`/`변경`/`삭제` 의 근거 누락
(`NO_EVIDENCE`) · 화면 ID 공란(`NO_SCREEN_ID`) · 인덱스 ↔ TSV 화면 집합 대조
(`SCREEN_MISSING`) · 렌더 결과에 빠진 화면(`MD_MISSING`) · 페이지 귀속 누락(`PAGE_GAP`) 은
**전수 판정이 끝나 있다.** 같은 것을 눈으로 다시 세지 않는다.

**다만 `MD_MISSING` 이 두 문서에 요구하는 것은 서로 다르다.** `03_기능_전체.md` 에는 **모든
화면**이 있어야 하고, `04_신규변경.md` 에는 **절을 얻는 분류(`신규`·`변경`·`삭제`·`확인 필요`)를
한 행이라도 가진 화면만** 있어야 한다. 전 행이 `미변경` 인 화면이 `04` 에 없는 것은 위반이
아니며 점검도 그 화면에는 `MD_MISSING` 을 내지 않는다 — 아래 오판 표의 같은 두 행이 같은
규칙을 반대편에서 적은 것이다. **「스크립트가 판정을 끝냈다」를 「모든 화면이 두 문서에 다
있어야 한다」로 읽지 마라** — 그렇게 읽으면 정상 산출을 누락으로 지적하게 된다.

종료 코드는 `0` 위반 없음 / `2` Critical / `1` Major 만 / **`3` 실행 오류**다.
`3` 을 `1` 로 읽지 마라 — 인자가 잘못돼 점검이 아예 돌지 않은 것을
*Critical 없음* 으로 읽으면 리뷰 전체가 근거를 잃는다.

**같은 함정이 `--pages` 에도 있다.** 이 인자는 **선택**이고, 빼면 페이지 커버리지 검사가
통째로 돌지 않는다 — **그런데 아무 경고도 나오지 않는다.** 나머지만 채점하고 `PAGE_GAP` 을
조용히 건너뛴 채 `✅ 결정적 점검 위반 0건` 을 찍는다. 값은 **기획서 문서의 총 페이지 수**이며
**오케스트레이터가 알고 있다** — 리뷰를 시작할 때 받아서 반드시 붙인다. 붙이지 않은 출력을
근거로 "어느 화면에도 귀속되지 않은 페이지는 없다"고 적으면 **검사하지 않은 것을 통과로
보고하는 것**이다.

**스크립트가 알지 못하는 것이 하나 있다 — 내지 않은 행이다.** 점검은 낸 행을 검사할 뿐이고,
한 화면에 행이 하나만 남아도 `SCREEN_MISSING` 은 울리지 않는다. **덜 읽은 화면을 찾는 것이
이 리뷰의 몫**이며, 아래 점검 항목이 그것을 겨눈다.

## 점검 항목 (판단이 필요한 것만)

| 점검 | 판정 |
|------|------|
| **분류 판정이 근거 태그와 맞는가** — `신규` 행의 근거가 `v1수정` 을 인용하는 식의 어긋남 | **Critical** |
| **삭제를 변경으로 섞었는가** — 취소선·`v1삭제` 근거인데 분류가 `변경` 인 행 | **Critical** |
| **전역 5개 섹션이 모두 다뤄졌는가** — Document History · Policy · Menu Structure · 기본 모드 공통 정의 · Wireframe 공통 표출 모달 정의 | Major |
| **기능 설명이 기획서 원문과 어긋나지 않는가** — 기획서가 적지 않은 동작을 채워 넣은 행 | Major |
| **「확인 필요」 항목에 판정 시도 흔적이 있는가** — 무엇을 보고 확정하지 못했는지가 화면 MD 에 없는 것 | Major |
| **화면당 기능 수가 3개 미만인데 사유가 없는가** — 덜 읽은 화면의 신호 | Major |
| **설명이 기능 요약을 넘어 절차·예상 결과로 번졌는가** | Minor |
| **근거 태그에 종류·일자 원문 인용이 없는가** (`날짜미표기`·`종류 원문 미표기` 도 인용으로 친다) | Minor |

- 「기획서 ↔ 기능 목록」 대조의 근거는 **렌더 이미지 원본**이다. 화면 MD 의 서술이 아니다
- **작성자 자기 점검 서술을 인용하지 말고 독립 실측하라**

## ⚠️ 역방향 오판 금지 — 이 절차에서는 여러 기준이 정반대다

**이것이 이 파일의 핵심이다.** 없으면 리뷰가 매 실행 "그 작업이 만들라고 한 것을 만들지 말라"는
지적을 내고 재작업 루프가 돈다. 이 저장소는 같은 방어를 이미 **여섯 번** 신설했다.

| 지적하면 오판인 것 | 이유 |
|---|---|
| **「분류 확인 필요」 행이 있다 / 많다** | **그것이 설계다.** 종류를 확정하지 못한 항목을 세 분류에 억지로 넣으면 기획서에 없는 종류를 단정하게 된다. `확인 필요` 는 판독 실패가 아니라 정상 산출이며, 그렇게 쓰라고 만든 값이다 |
| **IA(메뉴 트리)에 없는 화면이 있다** | IA 부재는 **신규의 *신호* 이지 근거가 아니다.** 실측 반례가 양쪽에 있다 — 신규인데 IA 에 이미 실려 있던 화면 19개, 기획서보다 낡은 IA. IA ↔ 기획서 차이는 렌더러가 대조 절로 **보고만** 하며 판정이 아니다 |
| **`구분` 분포가 프로파일과 다르다 / 분포 대조가 없다** | `구분` 은 **테스트 케이스 개념이고 여기엔 없다.** 이 절차에는 TC ID·우선순위·사전조건·예상 결과·`솔루션`·양식 프로파일이 전부 없다. 분포 대조 대상이 아니다 |
| **기획서에 없는 기능이 목록에 없다** | 기획서가 원천이다. 빠진 동작을 채워 넣는 것이 위반이지 비어 있는 것이 위반이 아니다 |
| **`미변경` 이 산출물의 대다수다 / 변경 검출이 부족하다** | **변경 문서에서는 대다수 기능이 실제로 손대지 않은 것이다.** `03_기능_전체.md` 는 기획서에 실린 모든 기능이고 모든 행이 분류를 달아야 하므로, 변경 표기가 없는 기능은 `미변경` 이 된다(실측 규모: 화면 127개 · 변경 항목 165건, 화면당 기능 3~10개면 손대지 않은 기능이 수백 건이다). 비율을 근거로 검출 부족을 주장하면 오판이며, **검출 누락은 비율이 아니라 원본 페이지 대조로 지적하라** |
| **`미변경` 절이 `04_신규변경.md` 에 없다** | 설계다. 그 문서에는 요약 표에만 집계되고 **절은 없다** |
| **전 행이 `미변경` 인 화면이 `04_신규변경.md` 에 제목으로 없다** | 설계다. `미변경` 은 절을 얻지 못하므로 그 화면은 `04` 에 실릴 자리가 아예 없고, **`03_기능_전체.md` 에만 있는 것이 맞다.** 점검도 그 화면에는 `MD_MISSING` 을 내지 않는다. 누락으로 지적하면 **해소할 방법이 없는 지적**이 된다 — 그 화면을 버리면 `03` 이 전체 기능 목록이 아니게 되고, 분류를 바꾸면 기획서에 없는 변경을 단정하게 된다. 반대로 `신규`·`변경`·`삭제`·`확인 필요` 를 한 행이라도 가진 화면이 `04` 에 없으면 그건 여전히 **Critical** 이다 |
| **`미변경`·`확인 필요` 행의 근거 열이 비어 있다** | 설계다. 두 분류 모두 *제시할 변경 근거가 없다* 는 것이 그 값의 뜻이라 근거를 요구하면 자기모순이다 — 점검도 이 두 행에는 근거를 묻지 않는다 |
| **`신규` 문서인데 `변경`·`삭제` 절이 `해당 없음` 이다** | 비교할 이전 회차가 없으므로 전 기능이 `신규` 인 것이 정상이다 |
| **CH-ID 가 없다 / 「박스 ↔ 확정 항목 대조표」가 없다** | 이 모드에는 CH-ID 가 없고 역추적 좌표는 **페이지 번호**다. `change-mode.md` 의 산출물 요구는 케이스 생성 경로의 것이다 (`digest-mode.md` D-7) |
| **`[취소선 pNNN]`·`[Menu Structure pNNN]` 이 사양 태그표에 없다** | 이 모드의 자체 태그이며 `digest-mode.md` D-5 가 단일 출처다. **`common.md` 태그표로 채점하지 않는다** — 이 저장소는 「사양에 없는 태그」 왕복으로 리뷰 사이클을 두 번 태운 적이 있다 |
| **화면 담당이 `03_기능_전체.md`·`04_신규변경.md` 를 쓰지 않았다** | 렌더러가 만든다. 화면 담당이 쓰면 같은 사실이 두 번 배열되어 두 문서가 어긋난다 |

**반대 방향도 함께 점검한다.** 위 목록은 **실제 결함을 통과시키라는 뜻이 아니다.**
예컨대 `확인 필요` 를 결함으로 지적하지 말라는 것은, 그 행에 **판정 시도 흔적조차 없는 것**까지
통과시키라는 뜻이 아니다 — "확인했는데 못 정했다"와 "안 봤다"는 다르고, 후자는 Major 다.
마찬가지로 `미변경` 비율을 지적하지 말라는 것은, **원본 페이지에 변경 표기가 실재하는데
`미변경` 으로 적힌 행**을 통과시키라는 뜻이 아니다 — 그건 Critical 이다.
