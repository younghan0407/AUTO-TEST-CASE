# PRD Digest Orchestrator

기획서(PRD) → 메뉴 트리 · 화면 인덱스 → **화면 배치 단위 순차 판독** → 두 축으로 렌더 →
전수 점검 + 집계 리뷰까지 수행한다. 산출물은 **사람이 읽는 문서 두 개**다 —
`03_기능_전체.md`(메뉴 구조 축)와 `04_신규변경.md`(변경 축).

## 트리거 키워드

- "기획서 분석해줘", "기획서 정리해줘"
- "기능 정리", "기능 목록 뽑아줘"
- "신규·변경 기능 파악", "이번 회차에 뭐가 바뀌었는지"
- "기획서 요약", "화면별 기능 요약"

## 실행 모드

| 에이전트 | 역할 | 호출 횟수 | 사용 참조 |
|---------|------|----------|----------|
| `prd-digester` | 화면 인덱스 얕은 스캔 · 전역 5개 섹션 판독 · 화면 배치 판독 | 1 + 1 + 배치 수 | `prd-analyzer` SKILL → `references/digest-mode.md` |
| `testcase-reviewer` | **집계 리뷰 1회** | 1 | `testcase-reviewer` SKILL → `references/digest-mode.md` |

**사이클 수는 `배치 수 + 3` 이다** (인덱스 1 + 전역 1 + 배치 M + 리뷰 1 — Phase 1 의 실행
순서와 같다).
실측 규모 기준(K8s 181페이지 · 화면 127개)으로 약 48회이고, 같은 기획서의 테스트 케이스
실행은 136회였다.

## 워크플로우

### Phase 0: 기본 정보 수집

#### 0-0. 작업 디렉터리 — 이 절이 경로의 단일 출처다

```
_workspace/
├── VIOLA-K8s_4.0_v1/          ← {디렉터리명}. 0-2 에서 확정한다
│   ├── shared/                ← {SHARED} : 이미지 · 검출 결과 + manifest.json (testcase-auto 와 공용)
│   ├── digest/                ← {WS} : 이 절차의 산출물
│   └── testcase/              ← 테스트 케이스 (testcase-auto)
└── augment/                   ← testcase-augment (제품·버전 폴더 밖)
```

- **`{WS}` = `_workspace/{디렉터리명}/digest`**, **`{SHARED}` = `_workspace/{디렉터리명}/shared`**
- `{SHARED}` 의 기본값은 위 경로이고, **0-2 (7) 에서 이미 변환된 이미지 경로를 받으면
  그 경로가 `{SHARED}` 가 된다.** 값을 받은 뒤로는 1-A 변환·1-A-2 판독 품질·1-A-3 변경
  표시 검출·manifest 가 **전부 그 한 트리**를 가리킨다
- **`shared/` 를 `testcase-auto` 와 공유하는 것이 이 배치의 목적이다.** 같은 판본의 기획서를
  두 절차가 각자 변환하면 이미지가 통째로 중복된다(실측: 작업 루트 484MB + 백업본 296MB로
  같은 PDF의 이미지가 780MB 중복됐다). 이 절차를 먼저 돌렸으면 `testcase-auto` 의
  Phase 0 (7) 에 이 `shared` 경로를 넘긴다
- **다른 절과 에이전트 프롬프트에서는 `_workspace` 를 쓰지 않는다.** 이 절에서 값을
  정하고, 이후로는 `{WS}`·`{SHARED}` 로만 지칭한다
- **에이전트에게는 치환된 실제 경로를 적어 넘긴다.** `{WS}` 를 그대로 프롬프트에
  넣지 않는다 — 에이전트가 치환하다 틀리면 엉뚱한 곳에 쓰고도 성공한 것처럼 보인다
- 스크립트를 호출할 때도 **항상 `--output-dir` / `--json` / `--out-json` / `--out-md` / `--ws`
  에 실제 경로를 명시**한다. 스크립트 기본값에 기대지 않는다. 예외는 **파일을 쓰지 않는
  훑기 호출**(`--no-crops`) 뿐이다

#### 0-1. 이 절차가 하지 않는 것

- **테스트 케이스를 만들지 않는다.** TC ID·`구분`·우선순위·사전조건·예상 결과·`솔루션` 은
  이 절차에 없는 개념이다
- **구글 시트를 쓰지 않는다.** `sheets_api.py` 를 호출하지 않으므로 대상 시트 URL 도,
  서비스 계정 공유도 필요 없다. 사용자에게 시트를 묻지 않는다
- **`.claude/formats/` 와 `build_brief.py` 를 쓰지 않는다.** 양식 프로파일(문체·분포·enum)은
  케이스 작성 규칙이라 여기에 적용할 자리가 없다. 브리핑은 `build_brief.py` 가 아니라
  1-D 가 직접 만든다
- **`sheet-analyst` 를 호출하지 않는다.** 대조할 시트가 없다

**케이스가 필요하면 `testcase-auto` 다.** 진행 중 케이스·시트가 필요해 보이면 스스로 만들지
말고 사용자에게 요청이 어느 절차로 가야 하는지 확인한다.

#### 0-2. 기본 정보 수집 — **필수 게이트**

**판독에 착수하기 전에 아래 7개 항목을 사용자에게 물어 확정한다.**
사용자가 첫 요청에 이미 적어 준 항목은 다시 묻지 말고 **확인만** 한다.
`AskUserQuestion` 으로 선택지를 제시하면 왕복이 줄어든다.

**추정 금지.** 답이 없으면 진행하지 않는다 — 잘못 추정한 항목 하나가 전 화면에 박힌다.

| | 항목 | 필수 | 비고 |
|---|------|------|------|
| 1 | **제품 유형** | 필수 | `VIOLA K8s` / `VIOLA CI/CD` / `TROMBONE`(중단) |
| 2 | **기획서 경로** | 필수 | PDF 또는 이미지(PNG 등) 파일·디렉터리 |
| 3 | **메뉴 IA 경로** | 선택 | 엑셀(`.xlsx`). 없으면 1-B 폴백 |
| 4 | **기획서 유형** | 필수 | `신규` / `변경` |
| 5 | **취소선 = 삭제 표기인가** | `변경` 일 때만 | 취소선은 색 검출에 잡히지 않는다 |
| 6 | **이미 아는 신규 화면 목록** | 선택 | 판정을 대신하지 않는다. **대조표로 보고만** 한다 |
| 7 | **이미 변환된 이미지 경로** | 선택 | 값이 있으면 그 경로가 `{SHARED}` 다 (0-0) |

**작업 디렉터리명도 여기서 확정한다.** 형식은 **`{제품}_{제품버전}_{문서회차}`**
(예 `VIOLA-K8s_4.0_v1`). 공백·슬래시는 `-` 로 바꾼다. **파일명에서 자동으로 만들지 않는다** —
`[4.0] VIOLA_화면기획서_v1_260728.pdf` 는 제품 버전이 `4.0`, Document History 회차가 `v1` 로
축이 둘이다. 회차가 없으면 같은 제품 버전 안에서 판본이 겹치고(CI/CD 기획서는 실제로
`v1` → `v2` 로 갱신됐는데 둘 다 `4.0` 이다), 제품 버전이 없으면 다음 릴리스의 `v1` 과 충돌한다.

##### (1) 제품 유형 — `TROMBONE` 은 진행하지 않는다

| 값 | 처리 |
|----|------|
| `VIOLA K8s` | 진행 |
| `VIOLA CI/CD` | 진행 |
| `TROMBONE` | **중단** — 아래 사유를 안내하고 진행하지 않는다 |

**`TROMBONE` 을 고르면 진행하지 않고 안내한다.** 기획서가 6개 파일로 쪼개져 있고 IA 도 따로
있으며, Screen ID 체계와 변경 표기 컨벤션을 **실측한 적이 없다.** VIOLA 규칙을 그대로 적용하면
화면 식별·분류 판정·근거 태그가 전 항목 틀린다. 이 저장소는 `profile-bootfactory` 를 실측 없이
파생으로 만들어 두고 **모든 문서에 계속 경고를 달아야 했던** 전례가 있다 — 같은 함정이다.

진행이 필요하면 **TROMBONE 기획서 1건과 그 IA 로 먼저 실측**하는 것이 정공법이다. 그 전까지는
사용자에게 미지원 사실과 사유를 알리고 멈춘다.

##### (4) 기획서 유형 — 분류 5종의 쓰임이 갈린다

| 값 | 판독 결과가 이렇게 된다 |
|----|----------------------|
| **`신규`** | **전 기능이 `신규`** 다. `미변경` 은 생기지 않는다 — 비교할 이전 회차가 없다. 렌더 결과의 `변경`·`삭제` 절이 `해당 없음` 인 것이 정상이며 누락이 아니다 |
| **`변경`** | **대다수 기능이 `미변경`** 이고 변경 표기가 붙은 것만 `신규`·`변경`·`삭제`·`확인 필요` 다 |

**`변경` 이어도 변경분만 뽑지 않는다.** 변경 표기가 없는 기능을 버리면 `03_기능_전체.md` 가
전체 목록이 아니게 된다. 변경분 한정은 `testcase-auto` 의 모드이고 이 절차가 아니다
(`digest-mode.md` D-7).

##### (6) 이미 아는 신규 화면 목록 — 판정을 대신하지 않는다

사용자가 신규 화면을 미리 알고 있으면 받아 두고, **판독이 끝난 뒤 대조표로만 보고**한다.
목록에 있다는 이유로 분류를 `신규` 로 정하지 않는다 — 분류의 근거는 주석 원문이다
(`digest-mode.md` D-3). **에이전트 프롬프트에 이 목록을 넣지 않는다.** 넣으면 판독 전에 답을
쥐여 주는 것이 되어 대조가 성립하지 않는다.

#### 0-3. 확정값 표로 되보여 준다

수집이 끝나면 **확정된 값을 표로 보여주고 진행한다.** 사용자가 오타나 오해를 잡을 마지막
지점이다.

```
다음 조건으로 기획서를 분석합니다. 테스트 케이스는 만들지 않습니다.

| 항목 | 값 |
|------|-----|
| 제품 유형 | VIOLA K8s |
| 기획서 | PDF/VIOLA_V4.0/[4.0] VIOLA_화면기획서_v1_260728.pdf |
| 메뉴 IA | IA/VIOLA_K8s_IA_260731.xlsx |
| 기획서 유형 | 변경 |
| 취소선 | 삭제 표기로 처리 |
| 이미 아는 신규 화면 | 없음 |
| 이미 변환된 이미지 | 없음 (새로 변환) |
| 작업 디렉터리명 | VIOLA-K8s_4.0_v1 |

산출물: 03_기능_전체.md (메뉴 구조 축) · 04_신규변경.md (변경 축)
※ 총 페이지 수는 묻지 않고 1-A 변환 결과에서 실측해 화면 인덱스 머리말에 적습니다.
```

#### 0-4. 기존 산출물 확인

| 상황 | 처리 |
|------|------|
| `{WS}` 가 없음 | **초기 실행** (Phase 1부터) |
| 있고 "다시"/"재실행" 요청 | `{WS}_prev_{설명}_{날짜}/` 로 이동. **`shared/` 는 제자리에 남긴다** |
| 있고 "특정 화면만 보완" 요청 | **부분 재실행** — 인덱스에서 그 순번을 찾아 해당 화면만 재판독하고 3 렌더부터 다시 돈다 |
| 있고 렌더·점검만 다시 | **재렌더** — 기획서를 다시 읽지 않는다. TSV 가 원천이므로 3 부터 시작한다 |

**`shared/` 를 남기는 것이 핵심이다.** 이미지는 판본이 같으면 같은 것이므로 이동 대상이
아니다. 작업 루트를 통째로 옮기면 이미지가 함께 사라져 재변환이 일어난다.

### Phase 1: 사전 준비

#### 1-A. 이미지 준비 — `testcase-auto` 1-A 와 같은 절차다

**PDF 입력인 경우 — 변환 전에 캐시를 검사한다.**

0-2 (7) 에서 이미 변환된 `shared` 경로를 받았으면 **`{SHARED}` 가 이미 그 경로다**(0-0).
이 절 아래의 `{SHARED}` 를 **전부** 그 값으로 치환하고 `--shared` 에만 따로 끼워 넣지
않는다 — 한쪽만 바꾸면 검사는 받은 트리에서 하고 변환은 기본 트리에 쏟아져 manifest 가
둘 생긴다.

```bash
python scripts/prd_cache.py check --pdf=<PDF> --shared={SHARED} --require=full,desc
```

네 상태(`CACHE_OK` / `CACHE_MISMATCH` / `CACHE_NO_MANIFEST` / `CACHE_PARTIAL`)의 처리는
`prd-analyzer` SKILL 「PDF-2.5. 이미지 캐시」가 단일 출처다. 여기에 복제하지 않는다.

**`--require=` 를 빼면 안 된다.** 이 인자가 없으면 `check` 는 매니페스트가 이미 아는
variant 만 검사하므로, `full` 만 등록된 트리가 `desc` 없이도 `CACHE_OK` 를 받는다. 그러면
DESC 조각 없이 진행해 판독 담당이 150 DPI 전체 페이지만 읽는다 — 오류는 나지 않고
**판독 품질만 조용히 떨어진다.** `full`·`desc` 라는 이름은 아래 `write` 의
`--variant=name=` 과 같은 것이며, 이 절에서 이름을 정하는 곳은 그 호출이다.

**받은 경로라도 `check` 는 반드시 한다** — 경로가 있다는 것과 그 이미지가 이 판본의
것이라는 것은 다르다.

```bash
# 전체 페이지 150 DPI
python scripts/pdf_to_images.py <pdf_path> --dpi=150 --output-dir={SHARED}/images

# Description 패널 크롭 200 DPI + 판독용 분할 (--tile=auto 필수)
python scripts/pdf_to_images.py <pdf_path> --crop-desc --dpi=200 --tile=auto --output-dir={SHARED}/images_desc
```

**`--tile=auto` 를 빼면 안 된다.** 이미지는 모델 전달 시 긴 변 1568px로 축소되므로 올린
DPI가 상한에서 버려진다 — 실측으로 DESC 크롭 200 DPI는 한글 본문 1자가 **9.9px** 로 도착해
판독이 안 되고, 에이전트가 영역을 다시 잘라 재판독하는 왕복이 생긴다. `--tile=auto` 는
조각을 상한 안에 넣어 **17.8px** 로 올리고 토큰도 페이지당 ~11.5K → ~6.5K 로 줄인다.

**총 페이지 수를 여기서 실측해 확정한다 — 4-1 `--pages` 의 원천이다.**

```bash
ls -1 {SHARED}/images | wc -l        # PDF 입력 — 전체 페이지 150 DPI 변환 결과를 센다
```

- `CACHE_OK` 로 변환을 건너뛰었으면 같은 명령으로 세고, `{SHARED}/manifest.json` 의
  `page_count` 와 **어긋나면 진행하지 않는다** — 둘이 다르면 트리가 온전하지 않다
- **이미지 입력이면 원본(또는 모아 둔) 디렉터리의 이미지 파일 수**가 총 페이지 수다
- 확정한 값은 **1-E 인덱스 머리말에 적는다.** 그 파일이 이 값의 단일 출처이고,
  4-1 과 4-2 가 거기서 읽는다

**사용자에게 묻지 않는다.** 이 값은 진술보다 실측이 정확하고(같은 이유로 변경 표시색도 묻지
않는다), 틀리면 `PAGE_GAP` 이 있지도 않은 페이지를 누락으로 올리거나 실재하는 누락을
놓친다 — 어느 쪽이든 검사가 무력해진다.

변환을 마쳤으면 **전량 성공한 뒤에만** manifest 를 쓴다. `--page-count=` 에는
**바로 위에서 센 값**을 넣는다 — 이 절에서 그 값을 확정한 뒤에 이 호출이 오는 이유다.

```bash
python scripts/prd_cache.py write --pdf=<PDF> --shared={SHARED} \
    --variant=name=full,dir=images,dpi=150,tile=none \
    --variant=name=desc,dir=images_desc,dpi=200,tile=auto \
    --page-count=<위에서 실측한 총 페이지 수>
```

**조각 파일 목록 전달 — 변환했든 캐시를 재사용했든 똑같이 한다.** 조각 파일명은
`page_NNN_desc_t1.png` ~ `_tN.png`(위→아래 순서, 경계 겹침 포함)이며 **화면 에이전트
프롬프트에 순서대로 넘긴다.** `CACHE_OK` 로 변환을 건너뛴 경우에도 건너뛰지 않는다 —
`ls -1 {SHARED}/images_desc` 로 목록을 만들어 넘긴다. 이 전달이 빠지면 판독 담당이 DESC
조각을 받지 못해 전체 페이지만 읽는다.

**이미지 입력인 경우 — 변환 없이 곧바로 진행한다.** 파일명 정렬이 페이지 순서와 다르면
(`1.png, 10.png, 2.png`) **사용자에게 순서를 확인한다.** 추정 금지. 흩어진 이미지는
`{SHARED}/prd_images/<name>/` 에 정렬 가능한 이름으로 모은다(원본은 수정·삭제하지 않는다).

#### 1-A-2. 이미지 판독 품질 게이트

```bash
python scripts/check_image_quality.py <이미지 디렉터리|파일> --json={SHARED}/00_image_quality.json
```

입력 인자는 **PDF 입력이면 `{SHARED}/images`**, 이미지 입력이면 사용자가 준(또는 모아 둔)
디렉터리다. 출력만 `{SHARED}` 로 고정된다.

| 판정 | 처리 |
|------|------|
| `OK` | 그대로 진행 |
| `주의` | **사용자에게 알리고** 진행. 해당 페이지 목록과 사유를 화면 에이전트 프롬프트에 전달 |
| `불가` | **사용자에게 알리고 원본 재전달을 요청.** 그대로 진행하면 그 페이지는 추측 없이 판독 불가로 남긴다 |

**사용자 통보는 의무다.** 판독이 안 되는 페이지를 조용히 넘기는 것은 누락이다.

#### 1-A-3. 변경 표시 검출 (기획서 유형이 `변경` 인 경우)

**먼저 이 기획서가 어떤 색을 쓰는지 실측한다.** 표시색은 기획서마다 다르고, 사용자 진술보다
스크립트 실측이 정확하다(2026-09-01 실측: 사용자가 알려준 파랑 후보 21건이 전부 오탐이었다).
**표시색을 묻지 않는다.**

```bash
# 0단계 — 쓰인 색 확인 (크롭도 메타 파일도 쓰지 않으므로 --output-dir 을 주지 않는다)
python scripts/detect_red_regions.py <입력> --color=both --no-crops

# 검출 — 전 페이지 1회 실행
python scripts/detect_red_regions.py <입력> --color=both --output-dir={SHARED}/red_regions
```

`<입력>` 은 **PDF 입력이면 PDF 원본 경로**다. `detect_red_regions.py` 는 PDF를 직접 열어
`--dpi` 로 스스로 렌더하므로, 렌더된 이미지 디렉터리를 주면 DPI 옵션을 무시하고 원본
해상도를 써 검출 조건이 달라진다.

```bash
# 취소선(삭제 표기) — 이 스크립트는 PDF 를 못 읽는다. 이미지만 받는다
python scripts/detect_strikethrough.py <이미지 디렉터리> --color-only --min-len=<실측값> --json={SHARED}/strikethrough.json
```

인자가 색 검출과 **정반대**이므로 돌려 쓰지 않는다. PDF 입력이면 1-A 가 만든
`{SHARED}/images` 다.

**`--min-len` 을 문서의 글자 폭으로 실측해 정한다.** 한글 가로획(`ㅗ` `ㅍ` `ㅌ` `ㅡ`)은 그
자체가 짧은 수평선이라, 임계값이 글자 폭보다 작으면 **글자획이 통째로 후보가 된다.** 폭은
DPI·폰트 크기에 따라 달라지므로 기본값(70px)을 그대로 쓰지 않고 이 기획서의 DESC 본문
한글 1자 폭을 재서 정한다(실측 참고: VIOLA V4.0 150 DPI 렌더는 **40~42px** → 70px 적정).

**양성 대조를 먼저 한다.** 취소선이 실재하는 페이지 하나에 돌려 그것이 검출되는지 확인한
뒤에야 나머지 페이지에 적용한다. **대조 없이 나온 「0건」은 *취소선이 없다* 가 아니라
*임계값이 안 맞는다* 일 수 있다.** 대조 대상과 임계값은 Phase 5 보고에 남긴다 — 어느 근거로
세운 값인지가 없으면 뒤에서 0건을 해석할 수 없다.

- **검출은 전 페이지에 1회만 실행한다.** 오케스트레이터가 화면 인덱스의 페이지 범위로
  결과를 잘라 각 화면 에이전트에게 넘긴다 — 화면마다 다시 돌리지 않는다
- 출력은 **후보**다. 오탐(필수 `*`, 원형 번호 배지, 에러 아이콘, 차트 색,
  **페이지 외곽 아트보드 프레임**, 파랑의 경우 링크·기본 버튼·선택 탭)이 섞여 있으므로
  화면 에이전트가 육안으로 확정한다
- **검출 0건은 「없음」이 아니다.** 양성 대조를 통과해도 부분 취소선은 임계값 아래로
  떨어진다(실측: 610px 런으로 세운 `--min-len=110` 이 같은 문서의 2글자 ~80px 취소선을
  놓쳤다). **「DESC 전문 육안 재판독」 의무를 화면 에이전트 프롬프트에 적어 넘긴다**
- **색으로 변경 종류·회차를 단정하지 않도록 지시한다.** 권위는 주석 원문(`v1추가`·`v1수정`·
  `v1삭제` + 날짜)이다
- 기획서 유형이 `신규` 면 이 절을 실행하지 않는다

#### 1-B. 메뉴 트리

```bash
python scripts/parse_menu_ia.py <IA.xlsx> --out-json={WS}/00_menu_tree.json --out-md={WS}/00_menu_tree.md
```

- 종료 코드 `0` 성공 / **`3` 파싱 실패**(`IA_NO_SHEET` · `IA_NO_HEADER` · `IA_NO_COLUMN` ·
  `IA_NO_LEVEL` · `IA_NO_OPENPYXL`). **`3` 을 보면 진행하지 않는다** — 실패 코드를 무시하고
  넘어가면 `00_menu_tree.json` 이 없거나 빈 채로 렌더에 들어가 전 화면이 「공통 정의
  (메뉴 경로 없음)」 절로 떨어진다
- `IA_NO_OPENPYXL` 은 의존성 문제다 — `pip install openpyxl` 을 안내한다
- 산출한 `00_menu_tree.md` 는 사람이 트리를 확인하는 용도이고, 렌더러가 읽는 것은
  `00_menu_tree.json` 이다. **두 파일을 모두 `{WS}` 에 만든다**

**IA 가 없으면** 기획서의 Menu Structure 페이지 + 각 화면 Breadcrumb 으로 폴백하고
**그 사실을 산출물 머리말에 남긴다.** 폴백이 남지 않으면 읽는 사람이 메뉴 경로를 IA 실측으로
오해한다. 이때 화면 전부가 「IA 에 없는 화면」이므로 1-C 의 목록은 전 화면이 된다.

#### 1-C. IA 는 권위가 아니다

**IA 부재는 신규 화면의 *신호* 이지 근거가 아니다.**

실측 반례가 양쪽에 있다 — `VIOE-03_02_05-*` **19개는 신규인데 IA 에 이미 실려 있고**,
CI/CD 는 IA(`260731`)가 기획서 v2(`260819`)보다 **낡았다.** 한쪽만 겪었다면 규칙을 반대로
세웠을 것이다.

- **IA ↔ 기획서 차이는 판정에 쓰지 않는다.** `04_신규변경.md` 의 「IA ↔ 기획서 대조」 절로
  **보고만** 한다. 렌더러가 그 절을 만든다
- **그 절이 실제로 내는 것은 비대칭이다** — IA 화면 수 · 기획서 화면 수 · 일치 수 **셋과**,
  `기획서에만 있음` **목록**이다. **IA 에만 있는 화면은 목록으로 나오지 않는다**(수에서
  빼야 알 수 있다). 산출물에 없는 것을 있다고 안내하지 않는다
- 분류 판정의 근거는 **주석 원문**이다 (`digest-mode.md` D-3)
- 0-2 (6) 의 「이미 아는 신규 화면 목록」도 같다 — 대조표로만 보고한다

**오케스트레이터만 할 수 있는 일 — 「IA 에 없는 화면」 목록을 만들어 프롬프트에 적어 준다.**

메뉴 트리는 `parse_menu_ia.py` 산출물이고 **화면 에이전트에게는 없다.** 에이전트는
`메뉴경로_폴백` 열을 이 목록의 화면에만 채우므로, 목록을 주지 않으면 채울 수 없고 추측하면
그룹핑이 깨진다.

목록은 **1-E 인덱스가 확정된 뒤** 낸다 — `00_menu_tree.json` 의 `screens[].screen_id` 집합과
인덱스의 화면 ID 집합을 비교해 **인덱스에는 있고 트리에는 없는 것**만 남긴다. 이 방향이
렌더러의 `기획서에만 있음` 목록과 같은 집합이다. 반대 방향(IA 에만 있는 화면)은 이 목록도
아니고 렌더러의 목록도 아니다 — **수로만 남는다.**

- **전 화면에 폴백을 채우게 하면 안 된다.** IA 에 있으면서 경로 레벨이 전부 `-` 인
  화면(`VIOE-00_00_*` 같은 공통 정의)은 경로가 **빈 문자열**로 조회되는데, 폴백이 차 있으면
  렌더러가 그 값을 써서 그 화면이 「공통 정의 (메뉴 경로 없음)」 절이 아니라 **엉뚱한 경로 절
  아래로 떨어진다**
- 목록이 비면 "IA 에 없는 화면 없음"을 프롬프트에 명시한다. 아무 말도 없으면 에이전트가
  목록을 요청해 왕복이 생긴다

#### 1-D. 판독 브리핑 생성 (에이전트 첫 호출 전 1회)

`{WS}/00_brief_digester.md` 를 만들어 `prd-digester` 호출 전부에 준다. **`build_brief.py` 를
쓰지 않는다** — 그 스크립트는 `.claude/formats/` 의 양식 사양을 역할별로 발췌하는 것이고, 이
절차는 양식 사양을 쓰지 않는다(0-1).

**이 절이 Phase 1 의 에이전트 호출보다 앞에 오는 이유** — `prd-digester` 는 착수 전에 이
파일을 **반드시 읽는 것**으로 정의돼 있다(에이전트 정의 「착수 전에 반드시 읽는다」).
뒤에 두면 **첫 호출이 없는 파일을 읽는다** — 에이전트가 멈추거나, 멈추지 않으면 TSV 형식을
스스로 지어내 그 산출물이 Phase 4 에서 `TSV_COLS`·`CLASS_ENUM` 으로 무더기로 잡힌다.
**1-E 화면 인덱스 스캔도 `prd-digester` 호출**이므로 브리핑은 그보다도 앞이다.
브리핑 내용은 Phase 0 확정값과 판독 절뿐이라 인덱스에 의존하지 않는다 — 앞에 둘 수 있다.

브리핑에 넣는 것:

- 0-3 확정값 표 (제품 유형 · 기획서 유형 · 취소선 처리 · 기획서 표기)
- `digest-mode.md` D-1 ~ D-7 **발췌 원문** — 요약하지 않는다. 요약본은 규칙을 조용히
  빠뜨리고, 빠진 규칙은 전 화면에 번진다
- (기획서 유형이 `변경` 이면) `change-mode.md` 에서 D-7 이 「가져오는 것」으로 지정한 절

**브리핑에 없는 규칙이 필요하면 에이전트가 원천 참조를 직접 열어도 된다** — 브리핑은 기본
로드를 줄이는 장치이고 원천 접근을 막는 장치가 아니다.

#### 1-E. 화면 인덱스 얕은 스캔 (에이전트 1회)

`prd-digester` 1회 호출로 전체 이미지를 순서대로 **얕게** 훑어 처리 단위 목록을 만든다.

**판독 깊이를 얕게 유지한다** — 화면 식별자 / 페이지 경계 / 화면 제목 / **전역 5개 섹션이
있는 페이지**까지만 본다. **본 판독은 Phase 2가 한다.** 여기서 깊이 읽으면 분석을 두 번 하는
것이다.

**전역 5개 섹션의 페이지 범위를 함께 잡는 것이 이 스캔의 두 번째 일이다.** 1-G 가 그 범위를
입력으로 받는다 — 여기서 잡지 않으면 1-G 호출에 넘길 페이지를 모른다.

- 입력: 전체 페이지 이미지(`{SHARED}/images`) · 조각 파일 목록(1-A) · 판독 이슈 페이지
  목록(1-A-2) · **`{WS}/00_brief_digester.md`**(1-D) · **1-A 가 실측한 총 페이지 수**
- 출력: `{WS}/00_screen_index.md`

**이 호출도 브리핑을 받는다** — `prd-digester` 는 착수 전 필수 읽기로 정의돼 있고, 이 절차에서
브리핑 없이 도는 에이전트 호출은 없다(1-D).

```
# 화면 인덱스

- 기획서: PDF/VIOLA_V4.0/[4.0] VIOLA_화면기획서_v1_260728.pdf
- **총 페이지 수: 181** (1-A 실측 — 4-1 `--pages` 가 이 값을 쓴다)
- 화면 식별자 출처: Screen ID
- 기획서 유형: 변경
- 메뉴 IA: IA/VIOLA_K8s_IA_260731.xlsx (299화면)
- 전역 5개 섹션: Document History p002 · Policy p003 · Menu Structure p009 ·
  기본 모드 공통 정의 p010 · Wireframe 공통 표출 모달 정의 p011 (1-G 입력)

| 순번 | 화면 ID | Page Title | 페이지 | 소속 간지 | IA | 배치 | 상태 |
|------|---------|-----------|--------|----------|-----|------|------|
| 01 | VIOE-02_01_01-10 | 통합 모니터링 | p012 | 모니터링 | 있음 | B01 | 대기 |
| 02 | VIOE-02_01_01-10 (flow) | 통합 모니터링 플로우 | p013 | 모니터링 | 없음 | B02 | 대기 |
```

- **헤더 행에 `화면 ID` 와 `Page Title` 이 반드시 있어야 한다.** `render_digest.py` 와
  `verify_digest.py` 가 **이 두 이름으로 헤더 행을 찾는다** — 둘 중 하나가 없으면 두
  스크립트가 인덱스를 통째로 못 읽고, 렌더는 화면명이 비고 점검은 `SCREEN_MISSING` 을
  한 건도 내지 못한 채 통과한다
- **화면 ID 를 다듬지 않는다.** 점검이 인덱스와 TSV 를 **정확 비교**하므로 공백·접미사를
  정규화하면 그 화면이 통째로 `SCREEN_MISSING` **Critical** 이 된다. 실측 인덱스에는
  `VIOE-02_01_01-10` 과 `VIOE-02_01_01-10 (flow)` 처럼 **공백으로만 갈리는 쌍**이 있다 —
  정규화하면 두 화면이 한 화면으로 뭉개진다
- 상태 enum: `대기` / `판독중` / `완료` / `실패`
- **소속 간지는 처리 단위가 아니라 그룹 라벨**이다. 배치 묶음 조건과 분석 컨텍스트로 쓴다
- **머리말의 「총 페이지 수」가 이 값의 단일 출처다.** 1-A 가 실측한 값을 그대로 옮기고,
  기억이나 사용자 진술로 바꾸지 않는다
- 화면 식별자를 어느 페이지에서도 찾지 못하면 인덱스를 만들 수 없다. 사용자에게 식별자
  필드명·위치를 확인한다. **임의로 폴백하지 않는다**

**배치 계획 — 묶음 조건은 `testcase-auto` 1-B-1 을 따르되 셋이다.**

| 조건 | 이유 |
|------|------|
| **같은 소속 간지** | 분석 컨텍스트가 같다 |
| **페이지 합 3장 이하** | 큰 화면을 묶으면 컨텍스트 한도·판독 누락 위험이 생긴다 |
| **한 배치 최대 3화면** | 그 이상은 묶지 않는다 |

**「같은 정책」 조건은 이 절차에 없다.** `prd-digest` 에는 정책 예외 개념이 없고 한 실행은
문서 전체를 같은 방식으로 읽는다(`digest-mode.md` D-7). 없는 조건을 묶음 판정에 넣지 않는다.

**첫 배치(`B01`)는 반드시 화면 1개다.** 1-F 다음의 첫 배치 검토가 문체·분류·태그 오류를
**전 화면에 번지기 전에** 잡는 것이므로, 첫 호출에 여러 화면을 넣으면 검토할 때 이미 여러
화면이 잘못 쓰여 있다.

**묶는 것은 호출뿐이고 산출물·상태는 화면별로 분리한다** — `02_screen_s{NN}.md` 와
`02_features_s{NN}.tsv` 를 화면마다 하나씩 만든다. 합쳐 저장하면 화면 하나만 다시 판독할 수
없어 부분 재실행이 깨진다.

#### 1-F. 사용자 확인 게이트 (필수)

화면 인덱스를 사용자에게 보여주고 확인받는다.

```
다음 화면 단위로 판독합니다. 맞는지 확인해 주세요.
화면 127개 → 배치 45개 → 에이전트 사이클 48회 (인덱스 1 + 전역 1 + 배치 45 + 리뷰 1)

| 순번 | 화면 ID | 페이지 | 소속 간지 | IA | 배치 |
|------|---------|--------|----------|-----|------|
| 01 | VIOE-02_01_01-10 | p012 | 모니터링 | 있음 | B01 (단독 — 첫 배치 검토) |
...

IA ↔ 기획서 차이: IA 화면 299 / 기획서 화면 127 / 일치 108
  → 기획서에만 있는 화면 19개는 04_신규변경.md 의 「IA ↔ 기획서 대조」 절에 목록으로 실립니다.
  → IA 에만 있는 화면(299 - 108 = 191개)은 그 절에 수로만 남고 목록은 없습니다.
  → 어느 쪽도 판정에 쓰지 않습니다.

전역 5개 섹션 (화면이 아니라 문서 축으로 따로 읽습니다):
  Document History p002 · Policy p003 · Menu Structure p009 ·
  기본 모드 공통 정의 p010 · Wireframe 공통 표출 모달 정의 p011

제외한 페이지: p001 · p004~p008 (표지·목차·간지) — 점검이 PAGE_GAP(Major)으로 보고합니다.
판독 불가: 없음

수정이 필요하면 알려주세요. OK면 그대로 진행합니다.
```

- **화면 수 · 배치 수 · 사이클 수 · IA 차이 · 전역 5개 섹션 페이지 범위 · 제외 페이지
  여섯을 반드시 보여준다.** 조용히 빠진 페이지가 누락의 원천이다
- **전역 섹션 페이지 범위를 빼면 안 된다.** 1-G 가 그 범위를 입력으로 받는데, 여기서
  보여주지 않으면 **사용자가 고칠 기회가 없는 값**이 그대로 다음 호출에 들어간다.
  1-E 의 얕은 스캔이 섹션 하나를 놓쳤거나 페이지를 잘못 잡았을 때 그것이 드러나는 곳은
  여기뿐이다 — 1-G 산출물에는 읽지 않은 섹션이 그냥 없는 것으로 나타난다
- **IA 차이는 산출물이 실제로 내는 형태로 안내한다** — 렌더러의 대조 절은 세 수(IA 화면 ·
  기획서 화면 · 일치)와 `기획서에만 있음` **목록**을 내고, **IA 에만 있는 화면은 목록이 없다.**
  게이트에서 목록이 나올 것처럼 말하면 사용자가 산출물에서 찾다가 없는 것을 찾게 된다
- **제외한 페이지는 `PAGE_GAP`(Major) 으로 남는 것이 정상이다.** 표지·목차는 기능 원천이
  없어 어느 화면에도 귀속되지 않는다. 게이트에서 사용자와 합의한 목록을 Phase 4 보고에
  그대로 인용해 「합의된 제외」임을 밝힌다 — 밝히지 않으면 읽는 사람이 판독 누락으로 읽는다
- 사용자 수정 → 인덱스 수정 후 다시 보여주고 재확인 (OK까지 반복)
- 확정된 인덱스는 `{WS}/00_screen_index.md` 에 저장한다
- 화면 수가 많으면 사이클 수를 알리고 **범위 축소 여부를 확인한다**

#### 1-G. 전역 5개 섹션 판독 (에이전트 1회)

`prd-digester` 1회 호출로 문서의 다섯 섹션을 읽는다 — Document History · Policy ·
Menu Structure · 기본 모드 공통 정의 · Wireframe 공통 표출 모달 정의.

**이 절이 1-E 뒤에 오는 이유** — 다섯 섹션이 **몇 페이지에 있는지는 인덱스 스캔이 확정한다**
(1-E). 인덱스보다 앞에 두면 오케스트레이터가 넘길 페이지 범위를 모른 채 호출하게 되어
문서 전체를 다시 훑히거나 섹션을 통째로 놓친다. **1-F 게이트 뒤인 것도 같은 이유다** —
게이트에서 페이지 범위가 수정되면 이 호출의 입력이 바뀐다.

- 입력: **1-E 가 확정한 그 섹션들의 페이지 범위**와 그 페이지 이미지 · 조각 목록 ·
  (변경이면) 검출 결과 · `{WS}/00_brief_digester.md`(1-D)
- 출력: `{WS}/01_global.md` + **`{WS}/02_features_s00.tsv`**(`화면ID` 열에 `문서 전역`)
- **「IA 에 없는 화면」 목록(1-C)은 넘기지 않는다** — 전역 행은 화면이 아니라 `메뉴경로_폴백`
  이 언제나 빈 칸이고, 목록을 주면 채울 이유가 없는 열을 채우게 된다

**전역 항목도 같은 TSV 형식으로 낸다.** 별도 파일·별도 형식을 만들지 않으므로 집계와 검증이
한 메커니즘으로 끝난다. 렌더러가 이 행을 `04_신규변경.md` 의 「문서 전역」 절로 보내고
`03_기능_전체.md` 에는 싣지 않는다 — 전역 정책은 화면 기능이 아니다.

**두 축을 모두 읽어야 하는 이유** — 화면만 보면 **신규 메뉴의 존재가 드러나지 않는다.**
Menu Structure 에 `v1추가` 로 표시된 메뉴가 정작 그 화면 페이지에는 아무 표기도 없을 수
있고, 실측에서 그 형태가 신규 메뉴 4개를 모두 만들어 냈다(K8s p009 의 `v1추가` 4건).

### Phase 2: 화면 배치 루프

1-F 에서 확정된 인덱스를 **배치 순서대로** 처리한다.

```
for 배치 in 배치 목록 (B01, B02, … 순):          # 1-E 배치 계획. 화면 1~3개
    배치 소속 화면 전부 → 상태 판독중
    prd-digester 1회 호출 → 화면별 02_screen_s{NN}.md + 02_features_s{NN}.tsv
    화면별로 상태 → 완료 (그 화면이 실패했으면 그 화면만 실패)
```

**`{NN}` 은 인덱스 순번이다.** 전역 판독(1-G)이 `s00` 을 쓰므로 화면은 `s01` 부터다.

**에이전트 프롬프트에 반드시 넣을 것 — 오케스트레이터만 가진 값이다:**

| 항목 | 없으면 어떻게 되나 |
|------|------------------|
| **화면 ID 원문 · 페이지 범위 · 화면 제목** | 인덱스 문자열을 **복사해** 넘긴다. 다듬으면 `SCREEN_MISSING` |
| **「IA 에 없는 화면」 목록** (1-C) | 에이전트는 메뉴 트리를 갖고 있지 않다. 없으면 폴백을 못 채우거나 추측해 그룹핑이 깨진다 |
| **조각 파일 목록** (1-A, 순서대로) | 전체 페이지(150 DPI)만 읽어 한글 1자 9.9px 로 판독한다 |
| **판독 이슈 페이지 목록** (1-A-2) | 판독 불가를 추측으로 채운다 |
| **(변경이면) 그 화면 페이지 분의 검출 결과 · 실측 표시색 · 확정 오탐 목록** (1-A-3) | 화면마다 검출을 다시 돌리거나 오탐을 변경분으로 센다 |
| **취소선 = 삭제 표기 여부** (0-2 (5)) | 삭제 변경분이 통째로 누락된다 |
| **`{WS}/00_brief_digester.md` 경로** (1-D) | 판독 절 없이 판독한다 |
| **`{WS}` 실제 경로** | `{WS}` 를 그대로 넘기면 에이전트가 치환하다 틀린다 |

**프롬프트에 넣지 않을 것** — 0-2 (6) 의 「이미 아는 신규 화면 목록」. 판독 전에 답을 주면
대조가 성립하지 않는다.

**인덱스 상태는 매 배치 후 갱신한다.** 이 파일이 진행 상태의 단일 출처이므로, 갱신하지 않으면
중단 후 이어 실행이 어디서 끊겼는지 알 수 없다.

#### 첫 배치 검토 (B01 직후, 1회)

`02_screen_s01.md` 와 `02_features_s01.tsv` 를 사용자에게 보여주고 진행 확인을 받는다.
이후 배치는 자동 진행한다. **여기서 볼 것은 넷이다** — 기능 단위의 굵기(3~10개) · 설명이
절차·예상 결과로 번지지 않았는가 · 분류가 다섯 값 안에 있는가 · 근거 태그에 종류·일자 원문이
인용됐는가.

**첫 배치에서 잡아야 나머지 화면에 번지지 않는다.** 실측 규모에서 배치는 45개다.

### Phase 3: 렌더

```bash
python scripts/render_digest.py --ws={WS} --product=<제품 유형> --doc=<기획서 표기>
```

**두 MD 는 한 벌의 TSV 에서 렌더된다.** 모델이 같은 사실을 두 축으로 두 번 배열하면 **두
문서가 어긋난다.** 화면 에이전트는 TSV 한 벌만 정확히 내고, 배열은 렌더러가 한다. 그래서
**기획서를 다시 읽지 않고 재렌더할 수 있고**, 기능 하나를 고치려면 TSV 한 줄만 고치면 된다.

| 종료 코드 | 뜻 | 처리 |
|----------|-----|------|
| `0` | `RENDER_OK 기능 N건 · 전역 항목 G건 · 화면 M개 · IA 있음/없음` | 4 로 간다. 이 줄의 수를 Phase 5 보고에 그대로 쓴다 — **`기능 N` 은 전역 항목을 뺀 수**이고 `03_기능_전체.md` 의 「기능 N건」과 같은 값이다 |
| `1` | **`--ws` 누락** — 사용법만 출력한다 | 실제 경로를 넣어 다시 돌린다 |
| `2` | **`TSV_COLS`**(셀에 탭·개행이 들어가 열 수가 어긋남) 또는 **`RENDER_NO_INPUT`**(`{WS}` 에 `02_features_s*.tsv` 가 없음) | 아래 |

**종료 코드가 `0` 이 아니면 두 MD 를 쓰지 않는다.** 파일이 아예 없거나 **직전 렌더 결과가
그대로 남는다** — 어느 쪽이든 Phase 4 는 `NO_MD` 또는 낡은 내용으로 채점한다.

- **`2` 를 보고 4 로 넘어가지 않는다.** 넘어가면 4-1 이 `NO_MD` 를 내고 그 지시(`3` 으로
  돌아간다)를 따라 같은 실패를 반복하는 **고리에 갇힌다** — 고리는 누군가 stderr 를 읽어야만
  끊긴다. `2` 는 **여기서** 해소한다
- `TSV_COLS` 는 **파일명과 행 번호를 함께 출력한다.** 그 화면 에이전트에게 그 행만 재작성을
  요청한다. **한 셀의 탭 하나가 렌더 전체를 멈추므로** 통째로 다시 판독할 일이 아니다
- `RENDER_NO_INPUT` 은 화면 판독이 하나도 없거나 `--ws` 가 다른 곳을 가리킨 것이다.
  실제 경로와 Phase 2 진행 상태를 함께 확인한다

- 산출물은 `{WS}/03_기능_전체.md`(메뉴 구조 축) · `{WS}/04_신규변경.md`(변경 축)
- **이 두 파일을 손으로 고치지 않는다.** 고치면 다음 재렌더에서 사라지고, 그 사이 TSV 와
  갈라진다. 고칠 것이 있으면 TSV 를 고치고 다시 렌더한다
- 메뉴 경로·화면명은 TSV 에 없고 렌더러가 `00_menu_tree.json` 과 인덱스의 `Page Title` 에서
  **조회한다** — 옮겨 적으면 IA 가 갱신될 때 산출물만 낡는다
- `--product` 와 `--doc` 은 산출물 머리말에 들어간다. IA 폴백을 썼으면(1-B) 그 사실을
  머리말에 함께 남긴다

### Phase 4: 검증 + 리뷰

#### 4-1. 결정적 점검

```bash
python scripts/verify_digest.py --ws={WS} --pages=<총 페이지 수>
```

| 종료 코드 | 뜻 | 처리 |
|----------|-----|------|
| `0` | 위반 없음 | 리뷰로 간다 |
| `1` | **Major 만** 있음 | 내용을 확인하고 리뷰로 간다 |
| `2` | **Critical 있음** | **통과할 때까지 고친다.** 아래 참조 |
| `3` | **실행 오류** | 점검이 아예 돌지 않았다. 인자를 고쳐 다시 돌린다 |

**`3` 을 `1` 로 읽지 않는다.** 인자가 잘못돼 점검이 돌지 않은 것을 *Critical 없음* 으로 읽으면
이후 보고 전체가 근거를 잃는다.

**`--pages` 를 반드시 붙인다.** 이 인자는 선택이고, **빼면 페이지 커버리지 검사가 통째로
돌지 않는데 아무 경고도 나오지 않는다.** 나머지만 채점하고 `PAGE_GAP` 을 조용히 건너뛴 채
위반 0건을 찍는다. 값은 기획서 문서의 **총 페이지 수**이며 **1-A 가 실측해 1-E 인덱스
머리말에 적어 둔 값**이다. 사용자 진술이나 기억이 아니라 그 파일에서 읽어 넣는다.

Critical 코드별 처리:

| 코드 | 무엇이 틀렸나 | 처리 |
|------|-------------|------|
| `TSV_COLS` | 셀에 탭·개행이 들어가 열 수가 어긋났다 | 그 화면 에이전트에게 해당 행 재작성 요청 |
| `CLASS_ENUM` | 분류가 다섯 값 밖이다 | 같음 |
| `NO_EVIDENCE` | `신규`·`변경`·`삭제` 행의 근거가 비었다 | 같음. 근거를 못 찾으면 `확인 필요` 로 옮기는 것이 정답이다 |
| `NO_SCREEN_ID` | 화면 ID 열이 비었다 | 같음 |
| `SCREEN_MISSING` | 인덱스에 있는데 TSV 에 없다 — **처리되지 않은 화면** | 그 화면을 다시 판독한다. 인덱스 상태를 함께 확인한다 |
| `MD_MISSING` | 렌더 결과에 화면이 빠졌다 | 3 렌더를 다시 돌린다. 그래도 남으면 TSV 를 본다 |
| `NO_MD` | 렌더를 아직 안 돌렸다 | 3 으로 돌아간다 |

**Critical 이 있으면 리뷰로 넘기지 않는다.** 고치고 재렌더한 뒤 다시 점검한다.

**점검이 알지 못하는 것이 하나 있다 — 내지 않은 행이다.** 점검은 낸 행을 검사할 뿐이고,
한 화면에 행이 하나만 남아도 `SCREEN_MISSING` 은 울리지 않는다. **덜 읽은 화면을 찾는 것은
4-2 리뷰의 몫**이다.

#### 4-2. 집계 리뷰 (에이전트 1회)

`testcase-reviewer` 를 **1회** 호출하고 `.claude/skills/testcase-reviewer/references/digest-mode.md`
를 읽도록 지시한다. 화면마다 리뷰를 돌리지 않는다 — 이 절차의 리뷰는 판정 타당성과 덜 읽은
화면을 보는 것이라 전체를 함께 봐야 한다.

- 입력: `{WS}` 실제 경로 · **총 페이지 수** · 4-1 점검 출력 · 기획서 유형 · 렌더 이미지 경로
- 출력: `{WS}/05_review.md`

**리뷰어 프롬프트에 반드시 넣을 오판 방지 항목:**

- **`확인 필요` 행이 있는 것은 정상 산출이다** — 종류를 확정하지 못한 항목을 세 분류에
  억지로 넣으면 기획서에 없는 종류를 단정하게 된다
- **`미변경` 이 대다수인 것은 정상이다** — `변경` 문서에서 대다수 기능은 실제로 손대지 않은
  것이다. 비율을 근거로 검출 부족을 주장하는 것은 오판이며, 검출 누락은 **원본 페이지 대조**로
  지적한다
- **전 행이 `미변경` 인 화면이 `04_신규변경.md` 에 없는 것은 설계다** — `미변경` 은 절을 얻지
  못한다. 점검도 그 화면에는 `MD_MISSING` 을 내지 않는다
- **`구분` 분포 대조는 대상이 아니다** — `구분`·TC ID·양식 프로파일이 이 절차에 없다
- **IA 에 없는 화면이 있는 것은 결함이 아니다** (1-C)
- **CH-ID·「박스 ↔ 확정 항목 대조표」가 없는 것은 설계다** — 역추적 좌표는 페이지 번호다
- **제외 페이지의 `PAGE_GAP` 은 1-F 에서 사용자와 합의한 것이다** — 그 목록을 함께 넘긴다

**⚠️ 서브에이전트 리턴은 20줄 이내로 제한한다.** 산출물은 **파일**이고 리턴은 **파일을
가리키는 영수증**이다. 리턴에 기능 표·판독 전문·위반 목록 전문을 담으면 그 텍스트가
오케스트레이터 컨텍스트에 쌓이고 이후 **모든 턴에서 다시 읽힌다**(실측: 화면 34개 실행에서
오케스트레이터 컨텍스트가 평균 40만 토큰까지 자라 전체 비용의 25.5% 를 혼자 썼다).

**렌더 결과와 판독 전문을 `Read` 로 열지 않는다.** 확인에 필요한 값은 이미 세 곳에서 온다 —
`render_digest.py` 의 **`RENDER_OK` 줄**(기능 수 · 전역 항목 수 · 화면 수 · IA 유무) · `verify_digest.py` 의
**위반 목록과 Critical/Major 건수** · 에이전트 리턴의 **분류별 건수**. 행 수·파일 크기가
필요하면 `wc -l` · `ls -l` 로 본다. **`verify_digest.py` 는 행 수도 파일 크기도 분류별 건수도
출력하지 않는다** — 없는 출력을 근거로 삼으면 확인했다고 적고 확인하지 않은 것이 된다.
상세를 알아야 할 때 **그때 파일을 연다.**

## 에러 핸들링

| 에러 유형 | 대응 |
|----------|------|
| `parse_menu_ia.py` 종료 코드 `3` | **진행 중단.** 코드별 사유를 사용자에게 알린다. `IA_NO_OPENPYXL` 이면 `pip install openpyxl` 안내 |
| IA 경로가 없음 (0-2 (3) 미입력) | 폴백으로 진행하고 **산출물 머리말에 그 사실을 남긴다.** 전 화면이 「IA 에 없는 화면」이 된다 |
| `prd_cache.py` `CACHE_MISMATCH` | **중단** — 다른 판본으로 만든 이미지다. 사용자 판단을 받는다 |
| 화면 식별자를 어느 페이지에서도 찾지 못함 | 인덱스 생성 불가 → 사용자에게 식별자 필드명·위치 확인 요청. **임의로 폴백하지 않는다** |
| 특정 페이지의 화면 ID 판독 불가 | 인덱스에 `[판독 불가]` 로 등재 + 1-F 에서 사용자 확인. 추정 금지 |
| 인덱스에 없는 화면 ID 가 판독 중 발견 | 보고 후 인덱스에 추가. **임의로 진행하지 않는다** — 인덱스가 진행 상태의 단일 출처다 |
| **배치 중 일부 화면만 실패** | 그 화면만 상태 `실패` 로 남기고 **배치의 나머지는 계속 진행**한다 |
| **배치가 컨텍스트 한도에 근접** | 그 배치를 화면 단위로 쪼개 재실행한다. 페이지 합 3장 조건을 넘겼는지 확인 |
| `verify_digest.py` 종료 코드 `3` | 점검이 돌지 않았다. **`1` 로 읽지 않는다.** 인자(특히 `--pages` 가 정수인지)를 고쳐 다시 돌린다 |
| `verify_digest.py` `NO_TSV` | 화면 판독이 하나도 안 됐거나 `{WS}` 경로가 틀렸다. 실제 경로를 다시 확인한다 |
| `SCREEN_MISSING` 이 다수 | 화면 ID 표기가 다듬어졌을 가능성이 크다. 인덱스 문자열과 TSV 를 글자 단위로 대조한다 |
| `PAGE_GAP` 이 합의된 제외 페이지 | 정상이다. 1-F 목록을 인용해 보고에 명시한다 |
| `PAGE_GAP` 이 합의 목록 밖 | **판독 누락이다.** 그 페이지가 어느 화면에 속하는지 확인해 재판독한다 |
| 제품 유형이 `TROMBONE` | **진행 중단** — 0-2 (1) 의 사유를 안내한다 |
| 사용자가 케이스·시트를 요구 | 이 절차가 아니다. `testcase-auto` 로 안내한다 (0-1) |
| 이미지 판독 품질 `불가` | 사용자 통보 + 원본 재전달 요청. 진행 시 그 페이지는 추측 없이 판독 불가로 남긴다 |
| Phase 0 필수 항목 미확정 | **진행 중단** — 사용자에게 묻는다. 추정 금지 |

**원칙:** 1회 재시도 후 재실패 시 해당 화면 결과 없이 다음 배치로 진행하고, 인덱스 상태를
`실패` 로 남기고 보고에 누락을 명시한다.
