# 팀 양식 사양 — TROMBONE 테스트케이스

이 파일은 **TROMBONE 제품 테스트 케이스 작성 양식의 기준(사양)** 이다. 매 실행마다 참고 시트를
다시 분석하지 않고 이 사양을 사용한다. 참고 시트는 **사양을 갱신할 때만** 읽는다.

VIOLA 양식과는 **문체·ID 체계·결합 규칙이 다르다.** 혼용하지 말 것 (아래 "VIOLA와 다른 점" 참조).

## 권위 규칙 — 사양과 대상 시트가 충돌할 때

케이스를 쓰기 전 `sheet-analyst`가 **대상 시트의 헤더 1행 + 마지막 20~50행**을 읽어 이 사양과 대조한다.

| 항목 | 권위 | 근거 |
|------|------|------|
| 컬럼 구조·순서·이름 | **대상 시트** | 어긋나면 값이 엉뚱한 칸에 들어간다 → **불일치 시 작성 중단 + 사용자 확인** |
| TC ID 마지막 번호 | **대상 시트** | 계속 자라는 값. 사양에 고정값을 두지 않는다 |
| enum 허용값 | **사양 기준** | 시트에 사양 외 값이 있으면 **보고 후 진행 여부 확인** |
| 문체·검증 단위·미사용 컬럼 정책 | **사양** | 실행마다 흔들리면 안 되는 값 |

### 이 사양이 낡았는지 알아내는 능력의 한계

드리프트 검증은 **헤더 1행 + 마지막 20~50행**만 읽는다.

| 팀 시트의 변화 | 잡는가 |
|----------------|-------|
| 컬럼 추가·삭제·이름·순서 변경 | **잡는다** (헤더 대조, Critical) |
| TC ID 증가 | **잡는다** (꼬리 실측) |
| 사양에 없는 enum 등장 | **잡는다** (꼬리 표본에 나타나면, Major) |
| **문체 전환** — 대괄호 → 백틱, 명사형 → 서술형 | **잡지 못한다** |
| **검증 단위 전환** — atomic → scenario | **잡지 못한다** |
| **미사용 컬럼 사용 시작** | **잡지 못한다** |
| **탭별 3 Depth 실사용 범위 변화** | **잡지 못한다** |

판정 항목이 헤더·enum·마지막 ID 세 가지로 한정된 의도적 범위 제한이다. 아래 신호가 보이면 갱신한다:
리뷰에서 문체·검증 단위 위반 반복 / 팀원이 양식 변경을 언급 / 생성 케이스가 기존 행과 이질적으로 보임.

## TC ID 체계

형식: **`TC_{모듈코드}_{3자리 zero-padded}`**

- **모듈코드는 탭(모듈) 단위로 고정**된다. VIOLA처럼 제품 전역 연속이 아니다
- `_New` 접미 탭은 **같은 모듈코드로 번호를 이어받는다** (리셋하지 않는다)
- `No`(A열)는 **탭 내 1부터 재시작**

| 모듈코드 | 탭 | 실측 번호 범위 | 화면 ID prefix |
|---------|----|--------------|---------------|
| `TKT` | `00.티켓` → `02.티켓_New` | 1~230 → **231~577** | `ADM-TCK-` |
| `BLD` | `00.빌드배포` → `04.빌드배포_New` | 1~511 → **512~1622** | `ADM-BDM-` |
| `PLY` | `01.정책` | 1~196 | (혼재 — 공통 UI 포함) |
| `SYS` | `03.시스템관리` | 1~602 | `ADM-SYS-` |
| `CMN` | `06.공통` | 1~425 | `CMN-HED-` `CMN-LOG-` `CMN-DAS-` `CMN-ERR-` |
| `GEN` | `07.일반` | 1~532 | `ADM-GEN-` |

- 결번: `BLD` **1건**, 나머지 0건. 중복 0건
- **마지막 번호는 사양에 고정하지 않는다.** 대상 시트(해당 모듈의 마지막 탭) 실측값 + 1 부터 시작

## 화면 ID (F열)

기획서 스펙 페이지 우측 상단 **`Page ID`** 를 원문 그대로 기입한다.
(필드명 우선순위: `Page ID` → `Screen ID` → 기타)

| 패턴 (숫자→N) | 건수 | 예 |
|--------------|------|-----|
| `ADM-BDM-NNNN-NN` | 1,621 | `ADM-BDM-0100-00` |
| `ADM-SYS-NNNN-NN` | 602 | `ADM-SYS-0200-02` |
| `ADM-TCK-NNNN-NN` | 577 | `ADM-TCK-0100-01` |
| `ADM-GEN-NNNN-NN` | 532 | `ADM-GEN-0102-05` |
| `CMN-HED-NNNN-NN` | 223 | 공통 헤더 |
| `CMN-LOG-` / `CMN-DAS-` / `CMN-ERR-` | 102 / 72 / 28 | 공통 로그·대시보드·에러 |
| **`II-N.N` / `I-N`** | 122 / 35 | **정규 형식이 아닌 값** — 기획서 원문이 그러하다 |

- **구분자·형식을 임의로 통일하지 않는다.** `II-2.1` 같은 비정규 값도 기획서 원문이면 그대로 쓴다
- **유추로 만들지 않는다.** 기획서에서 직접 확인한다
- 모듈 구분은 솔루션 컬럼이 아니라 **탭 + TC ID 모듈코드 + 화면 ID prefix**로 수행한다

### 팝업 처리 (실측)

- 팝업은 **2 Depth에 별도 값으로 분리** (예: `결재 라인 팝업`, `업무코드 관리 팝업`)
- 3 Depth는 **고정되지 않는다** — 팝업 성격에 따라 `생성`(15) / `목록`(9) / `상세`(17) / `-`(15) 사용
  (VIOLA는 팝업→`상세` 고정. **여기서는 화면 성격을 따른다**)
- 화면 ID는 팝업 고유 ID가 있으면 그것을, 없으면 모 화면 ID를 쓴다

- **여러 동작을 한 TC에 묶지 않는다** (시나리오 금지)

## 표기 컨벤션

### ⚠️ UI 라벨 표기 — **대괄호를 쓴다. 백틱을 쓰지 않는다**

VIOLA와 **정반대**다. 가장 눈에 띄는 문체 차이이므로 혼동하지 말 것.

| | TROMBONE | VIOLA |
|---|---|---|
| 절차의 백틱 사용 | **0.0%** (0/3,953) | 65% |
| 절차의 대괄호 사용 | **34.8%** (1,376) | — |
| 예상 결과 백틱 | **0.7%** (27) — 형식 문자열 한정 | 52% |

- 버튼·메뉴는 `[등록]`, `[검색]`, `[삭제]` 처럼 **대괄호**로 감싼다
- 백틱은 **형식 문자열에만 소량** 사용 (`` `yyyy-mm-dd hh:mm:ss` ``, `` No-data 마커 `-` ``)

### 절차(P)

- **`1. ` 접두 100%** — 숫자 + 마침표 + 공백 1칸. 예외 없음

## 비고(V) / 피드백(W) 역할

**두 열의 역할이 분리되어 있다.** V=근거 / W=확인사항.

### V열 = 비고 (근거 태그) — **3,953/3,953 (100%) 필수**

| 태그 | 용도 |
|------|------|
| `[DESC ❶]` / `[DESC ❶-N]` / `[DESC ❶-N-a]` | 기획서 Description 항목 번호 근거 (원문자 ❶~❾ + 하위 번호). 최다 |
| `[공통 DESC]` | 여러 화면 공유 공통 동작 근거 (362) |
| `[DESC II-N.N]` | 비정규 화면 ID 체계 페이지의 Description 근거 (122) |

- 태그 뒤에 한 줄 설명을 덧붙일 수 있다
- **비고를 비우는 행은 이 시트에 단 한 건도 없다**

### W열 = 피드백 (확인사항 태그) — 254행 (6.4%)

| 태그 | 건수 |
|------|------|
| `[기획 확인]` | 147 |
| `[확인 불가]` | 38 |
| `[기획 확인 후 예상결과 확정]` | 3 |
| `[UI↔DESC 불일치]` | 2 |

### ⚠️ 소수 혼용에 대한 방침

`07.일반` 탭에 **혼용이 있다** — W열에 `[DESC …]` 근거 태그가 든 행 **21건(4%)**,
V열에 `[확인 불가]` 확인사항이 든 행 23건.

**신규 작성은 분리를 따른다: V=근거 태그 / W=확인사항.**

판단 근거:
1. 전수로 보면 대세가 분리다 (V 100% 근거 / W는 `[기획 확인]`·`[확인 불가]` 지배)
2. 하네스의 기존 규칙이 V/W 분리를 전제한다 (`testcase-generator` 0-E: UI↔DESC 불일치는 확인사항)
3. 혼용은 `07.일반` 한 탭의 4%에 국한된다

**기존 혼용 행을 위반으로 지적하지 않는다.** 리뷰 대상은 신규 작성 행이다.
팀이 혼용을 의도한 컨벤션으로 확인해 주면 이 항목을 재검토한다. **[팀 확인 대기]**

## 탭 구조 / 작성 절차

- 탭 분할 기준 = **기능 모듈별** (티켓 / 빌드배포 / 정책 / 시스템관리 / 공통 / 일반)
- `_New` 접미 탭 = 같은 모듈의 후속 케이스를 번호 이어서 쓰는 증분 탭
- 모든 탭의 1행 헤더는 A~W 23컬럼 동일 (`07.일반`의 A1 공란은 예외)
- TC ID는 모듈 단위 연속, `No`는 탭별 재시작

**신규 탭에 작성하는 절차:**

1. `add_tab` 으로 대상 탭 생성 (모듈명 + 필요 시 `_New`/`_vN` 접미)
2. `write` — `'{탭명}'!A1:W1` 에 위 **헤더 원문** 기입
3. `append` — 2행부터 케이스 batch 1회 전송
4. `updatedRange` 확인 후 보고
5. 빈 기본 탭은 API로 삭제할 수 없다 → 사람이 수동 정리

## VIOLA와 다른 점 (혼용 주의)

두 사양을 헷갈리면 케이스가 팀 컨벤션에서 벗어난다. **차이가 큰 항목만 모았다.**

| 항목 | TROMBONE | VIOLA |
|------|----------|-------|
| 솔루션 | `TROMBONE` | `VIOLA` |
| 화면 식별자 필드 | **`Page ID`** — `ADM-GEN-0101-01` | `Screen ID` — `VIOE-02_01_01-11` |
| TC ID | `TC_{모듈}_{3자리}` — **모듈별 연속** | `TC_VIO_{3자리}` — **제품 전역 연속** |
| UI 라벨 표기 | **대괄호 `[등록]`** (백틱 0%) | **백틱** (52~65%) |
| 지배 구분 | **`정상` 65%** | `표시` 56% |
| `정상`의 우선순위 | **P1~P4 전부** (P3 60%) | P1/P2만 (P3·P4 0건) |
| `표시`의 우선순위 | **항상 P3** | P3 기본 (P2 4건) |
| 사전조건 | **공란 허용** (92.1% 채움) | 100% 채움 |
| 3 Depth | **7종, 탭별 범위 다름** | 4종 고정 |
| 팝업 3 Depth | **화면 성격에 따름** | `상세` 고정 |
| 1 Depth | 탭당 1~7종 | 탭당 1개 |
| 메시지 코드 | **`CMN001` 등 인용** | 없음 |
| A1 헤더 | `No` (`07.일반`만 공란) | `No` |

## 새 케이스 작성 시 암묵 규칙 (요약)

1. **컬럼 23개 순서 고정.** X열 이후 쓰지 않는다
2. **비고(V)를 비우지 않는다.** 근거 태그 필수 (3,953/3,953)
3. **R·S·T·U·D·E는 공란.** `PASS` 등을 임의로 채우지 않는다
4. **4·5 Depth는 `-`**, 사전조건·테스트 데이터는 불필요하면 **빈칸**
5. **`표시` → 항상 `P3`. `부수` → 항상 `P4`** (각 100%)
6. **`정상`에 P3·P4를 쓸 수 있다** — VIOLA 규칙을 적용하지 말 것
7. **UI 라벨은 대괄호** `[등록]`. 백틱은 형식 문자열에만
8. **atomic 유지** — 절차 1단계, 예상 1줄, 사전조건 1줄
9. **화면 ID는 기획서 `Page ID` 원문.** 비정규 값(`II-2.1`)도 원문대로. 유추 금지
10. **솔루션은 `TROMBONE` 고정**
11. **3 Depth는 그 모듈이 실제로 쓰는 범위**를 따른다 (대부분 `목록`/`상세`/`생성` 3종)
12. **메시지 코드가 기획서에 있으면 예상 결과에 인용** (`CMN001` 등)
13. **기획서 미정의 항목도 케이스로 만든다** — W열에 `[기획 확인]` / `[확인 불가]`
14. **UI↔DESC 불일치는 W열에 기재**
15. **예상 결과 종결은 명사형** (`~노출`/`~출력`/`~호출`). `~된다` 지양
16. **TC ID는 해당 모듈 마지막 탭의 실측 마지막 번호 + 1** 부터
