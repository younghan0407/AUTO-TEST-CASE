**`common.md` 와 함께 읽어야 한다.** 이 파일은 TROMBONE에서만 다른 값을 담는다.
공통 규칙(컬럼 골격·헤더 원문·`-` vs 빈칸·atomic·태그 체계·C-ID/CH-ID·변경분 모드)은 `common.md`.

> **⚠️ VIOLA 프로파일과 문체가 정반대다.** UI 라벨을 **대괄호**로 감싸고 **백틱을 쓰지 않는다**
> (절차 백틱 0.0% — 0/3,953행). 지배 구분도 `정상`(65%)으로 VIOLA(`표시` 56%)와 반대다.
> 두 프로파일을 헷갈리면 케이스가 통째로 다른 팀 것처럼 보인다.

기획서 스펙 페이지 우측 상단 **`Page ID`** 를 원문 그대로. 필드명 우선순위 **`Page ID` → `Screen ID` → 기타**.

| 패턴 (숫자→N) | 건수 | 예 |
|--------------|------|-----|
| `ADM-BDM-NNNN-NN` | 1,621 | `ADM-BDM-0100-00` |
| `ADM-SYS-NNNN-NN` | 602 | `ADM-SYS-0200-02` |
| `ADM-TCK-NNNN-NN` | 577 | `ADM-TCK-0100-01` |
| `ADM-GEN-NNNN-NN` | 532 | `ADM-GEN-0102-05` |
| `CMN-HED-` / `CMN-LOG-` / `CMN-DAS-` / `CMN-ERR-` | 223 / 102 / 72 / 28 | 공통 헤더·로그·대시보드·에러 |
| **`II-N.N` / `I-N`** | 122 / 35 | **정규 형식이 아닌 값** — 기획서 원문이 그러하다 |

**비정규 값(`II-2.1`)도 기획서 원문이면 그대로 쓴다.** 형식을 임의로 통일하지 않는다.

## enum — TROMBONE 실측

### 우선순위 분포

**P3 59.2%(2,339) · P2 20.6%(813) · P1 11.1%(437) · P4 9.2%(364)**

### 구분 분포 — 지배 구분은 **`정상`**

**정상 65.1%(2,574) · 엣지 22.2%(879) · 비정상 9.4%(373) · 표시 2.4%(93) · 인터랙션 0.6%(25) · 부수 0.2%(9)**

> **지배 구분은 `정상` 이다. VIOLA는 `표시` 가 과반이지만 TROMBONE은 정반대다.**
> **`표시` 비중이 낮은 것이 이 양식의 정상 상태**이며 커버리지 부족 신호가 아니다.
> 표시 검증을 요소 단위로 무한히 쪼개지 않고 팀이 실제로 쓰는 수준으로 묶는다.

> **실측 경고:** 이 프로파일이 없던 시절 하네스 출력(`일반 v2` 763행)은 `표시` **+29.4%p** /
> `정상` **−44.9%p** 편차를 냈다. VIOLA 정책이 제품 무관하게 적용된 결과다.

### 구분 × 우선순위 결합 규칙 (실측)

| 구분 | 관측 분포 | 규칙 |
|------|----------|------|
| `정상` (2,574) | P3 1,537 / P1 428 / P2 416 / **P4 193** | **P1~P4 전부 사용.** P3가 기본(60%) |
| `엣지` (879) | P3 586 / P2 151 / P4 139 / P1 3 | P3 기본 |
| `비정상` (373) | P2 242 / P3 108 / P4 23 | **P2 기본** |
| `표시` (93) | **P3 93 — 100%** | **항상 `P3`** (예외 0건) |
| `인터랙션` (25) | P3 15 / P1 6 / P2 4 | P3 기본 |

> **VIOLA와 다르다.** VIOLA는 `정상` 에 `P3`/`P4` 를 준 사례가 0건이지만, TROMBONE `정상` 은
> P3가 60%이고 P4도 193건 있다. **VIOLA 규칙을 여기 적용하지 말 것.**

### 3 Depth (K) — 7종, **탭별 실사용 범위가 다르다**

전체 허용: `상세` / `목록` / `생성` / `-` / `등록` / `검색` / `수정`
(분포: 상세 2,181 · 목록 850 · 생성 785 · `-` 69 · 등록 28 · 검색 24 · 수정 16)

| 탭 | 실사용 3 Depth |
|----|---------------|
| `00.티켓` `00.빌드배포` `01.정책` `02.티켓_New` `03.시스템관리` `04.빌드배포_New` | **`목록` / `상세` / `생성` 3종만** |

## V/W 소수 혼용에 대한 방침

`07.일반` 탭에 혼용이 있다 — `피드백` 열에 `[DESC …]` 근거 태그가 든 행 **21건(4%)**,
`비고` 열에 `[확인 불가]` 확인사항이 든 행 23건.

**신규 작성은 분리를 따른다: 비고=근거 태그 / 피드백=확인사항.**

판단 근거: ① 전수로 보면 대세가 분리다 (비고 100% 근거 / 피드백은 `[기획 확인]`·`[확인 불가]` 지배)
② 하네스 기존 규칙이 분리를 전제한다 ③ 혼용은 `07.일반` 한 탭의 4%에 국한된다.

**기존 혼용 행을 위반으로 지적하지 않는다.** 리뷰 대상은 신규 작성 행이다. **[팀 확인 대기]**

### 피드백 태그 실측 분포

`[기획 확인]` 147 · `[확인 불가]` 38 · `[기획 확인 후 예상결과 확정]` 3 · `[UI↔DESC 불일치]` 2

### 비고 태그 실측

`[DESC ❶]` / `[DESC ❶-N]` / `[DESC ❶-N-a]` — **원문자 ❶~❾ + 하위 번호** (최다)
`[공통 DESC]` (362) · `[DESC II-N.N]` (122, 비정규 화면 ID 페이지)

> TROMBONE은 DESC 항목을 **원문자(❶)** 로 인용한다. VIOLA의 `[DESC N항]` 과 표기가 다르다 —
> 어느 쪽이든 **기획서 원문 표기를 따른다.**

## TROMBONE 암묵 규칙 (프로파일 고유분만)

1. **솔루션은 `TROMBONE` 고정**
2. **TC ID `TC_{모듈}_{3자리}`, 모듈 단위 연속** — 해당 모듈 마지막 탭의 실측 마지막 번호 + 1 부터
3. **`1 Depth` 는 탭당 1~7종**
4. **사전조건·테스트 데이터는 불필요하면 빈칸** (`-` 아님)
5. **`표시` → 항상 `P3`. `부수` → 항상 `P4`** (각 100%)
6. **`정상` 에 P3·P4를 쓸 수 있다** — VIOLA 규칙을 적용하지 말 것
7. **UI 라벨은 대괄호** `[등록]`. 백틱은 형식 문자열에만
8. **`3 Depth` 는 그 모듈이 실제로 쓰는 범위**를 따른다 (대부분 `목록`/`상세`/`생성` 3종)
9. **메시지 코드가 기획서에 있으면 예상 결과에 인용** (`CMN001` 등)
10. **팝업 `3 Depth` 는 화면 성격에 따름** (VIOLA처럼 `상세` 고정 아님)
