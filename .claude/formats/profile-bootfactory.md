# 제품 프로파일 — BootFactory

**`common.md` 와 함께 읽어야 한다.** 이 파일은 BootFactory에서만 다른 값을 담는다.
공통 규칙(컬럼 골격·헤더 원문·`-` vs 빈칸·atomic·태그 체계·C-ID/CH-ID·변경분 모드)은 `common.md`.

## ⚠️ 이 프로파일은 실측이 아니라 파생이다

| 항목 | 값 |
|------|-----|
| 프로파일 이름 | `profile-bootfactory` |
| 대응 제품 유형 | **`BootFactory`** (Phase 0 제품 유형) |
| 버전 | 1.0 (2026-09-02 신설) |
| **측정 대상** | **없음 — 팀 작성 BF 시트를 측정한 적이 없다** |
| 파생 근거 | **`profile-viola` 문체·규칙 승계** (사용자 결정 2026-09-02) |

**BF 실측 근거 0건이다.** 아래 값 중 화면 ID 패턴을 뺀 전부가 VIOLA에서 이식한 값이며,
팀 BF 시트가 실제로 이 컨벤션을 쓰는지 확인된 바 없다.

**팀이 이미 쓰는 BF 원본 시트가 나오면 `"참고 시트로 양식 사양 갱신해줘"` 로 전수 스캔해
이 프로파일을 실측으로 교체하는 것이 정공법이다.**

### 근거 없는 값 — 바꾸려면 비싸다

`솔루션` 고정값과 TC ID 모듈코드는 **전 행에 박히는 상수**라 나중에 바꾸려면 열 전체를 고쳐야 한다.
아래는 제안값이며, 팀 리더가 확정해 주면 이 파일을 갱신한다.

| 항목 | 제안값 | 근거 |
|------|-------|------|
| `솔루션`(B) | **`BOOTFACTORY`** | VIOLA 컨벤션(제품명 대문자, 구분자·접미사 없음) 적용. 차선 `BF`, 비권장 `BOOT_FACTORY`(VIOLA에 언더스코어 사례 0건) |
| TC ID 모듈코드 | **`BF`** | VIOLA의 `VIO` 는 모듈명이 아니라 제품 약어이고, TC ID가 제품 전역 연속이므로 모듈별 코드는 연속성을 깬다. `BF` 는 하네스가 이미 쓰는 정식 약어 |

> 이 `솔루션` 값은 향후 `sheet-analyst` 의 **프로파일 자동 판정 키**이기도 하다.

## 화면 ID (F열)

필드명 우선순위 **`Screen ID` → `Page ID` → 기타**.

| 패턴 | 예 | 근거 |
|------|-----|------|
| `BOOT-NN_NN_NN` | `BOOT-03_01_01` · `BOOT-03_01_08` | **실측** (2026-09-01 `멤버 관리 > 사용자` 기획서 6페이지) |

VIOLA(`VIOE-NN_NN_NN`)와 **같은 계열 형식**이다. 구분자를 임의로 통일·변환하지 않고
기획서 원문 그대로 기입한다.

## enum — VIOLA 분포 이식 (BF 실측 아님)

### 우선순위 분포

**P3 74.9% · P2 13.0% · P4 6.9% · P1 5.1%**

### 구분 분포 — 지배 구분은 **`표시`**

**표시 55.9% · 엣지 14.5% · 인터랙션 11.2% · 부수 6.9% · 정상 6.3% · 비정상 5.1%**

> **이 분포는 VIOLA 331행 실측을 이식한 값이다.** BF 팀 시트가 다른 분포를 쓸 수 있다.
> 리뷰에서 편차가 반복 지적되면 사양 갱신을 검토한다.

### 구분 × 우선순위 결합 규칙 (VIOLA 승계)

| 구분 | 우선순위 |
|------|---------|
| `부수` | **항상 `P4`** |
| `정상` | **`P1` 또는 `P2` 만** |
| `비정상` | `P2` 기본 |
| `표시` / `인터랙션` / `엣지` | `P3` 기본. **`표시` 에 `P1` 금지** |

### 3 Depth (K) — 4종 고정 (VIOLA 승계)

`목록` / `생성` / `수정` / `상세` 중 택일. **팝업·모달 → `상세` 고정.**
`등록`/`검색`/`-` 도입 금지.

## 표기 컨벤션 — VIOLA 승계

### UI 라벨 = **백틱**

- 감싸는 대상: UI 레이블·버튼명·컬럼명·상태 enum·메시지 원문·형식 문자열
- **대괄호 `[ ]` 는 태그 전용** (비고·피드백). 본문 문체에 쓰지 않는다

> **TROMBONE 문체(대괄호)를 섞지 마라.**

### 절차·예상 결과

| 지표 | 목표 |
|------|-----|
| 절차 | **`1. ` 접두 100%**, 1단계 원칙 (최대 2) |
| 예상 결과 | **명사형 종결**, 1줄 원칙 (최대 2). 하위는 `ㄴ` 최대 1개 |
| 사전조건 | 1줄 |

### 일시·날짜 형식

기본형 `yyyy-mm-dd hh:mm:ss`.

## BootFactory 암묵 규칙 (프로파일 고유분만)

1. **솔루션은 `BOOTFACTORY` 고정** (제안값 — 팀 확정 시 갱신)
2. **TC ID `TC_BF_{3자리}`, 제품 전역 연속, 화면 단위 블록**
3. **`1 Depth` 는 탭당 1개 값** — 기획서 Breadcrumb 최상위 원문
4. **사전조건 채움 필수**
5. **`부수` → 항상 `P4`. `정상` 에 `P3`/`P4` 를 주지 않는다. `표시` 에 `P1` 금지**
6. **UI 레이블은 백틱 + 기획서 원문 인용.** 대괄호는 태그 전용
7. **팝업 `3 Depth` 는 `상세` 고정**
8. **이 프로파일의 값은 실측이 아니라 VIOLA 이식임을 항상 염두에 둔다** — 리뷰에서 편차가
   반복되면 프로파일이 틀린 것일 수 있다
