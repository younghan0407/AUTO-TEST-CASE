### `K8s` 와 `CI/CD` 는 같은 프로파일을 쓴다

제품 유형이 `VIOLA K8s` 든 `VIOLA CI/CD` 든 **양식은 동일하다.** 둘의 차이는 시트 컬럼이 아니라
**탭 분리 + `1 Depth`(Breadcrumb 최상위 원문)** 로 표현된다.

| 제품 유형 | `1 Depth` 예 | 리소스 어휘 |
|-----------|-------------|------------|
| `VIOLA K8s` | `Kubernetes Engine` 등 기획서 Breadcrumb 원문 | `파드`·`디플로이먼트`·`데몬셋`·`네임스페이스`·`클러스터` |
| `VIOLA CI/CD` | CI/CD 계열 Breadcrumb 원문 | `파이프라인`·`빌드`·`배포 이력`·`아티팩트` |

> **`1 Depth` 값을 제품 유형에서 만들어내지 마라.** 기획서 Breadcrumb 최상위 **원문**을 쓴다.
> 제품 유형은 분석 컨텍스트(어느 영역 기획서인지)일 뿐 컬럼 값의 출처가 아니다.

> **2026-09-02 이전 케이스와의 차이** — 그 전에는 `관리대상` 전용 컬럼(구 C열)에 `K8S`/`CI·CD`/`BF(공통)`
> 를 행마다 기입했다. 이 컬럼은 폐지됐다. 기존 24컬럼 탭에 이어 쓸 때는 `common.md` 의 권위 규칙에
> 따라 **대상 시트 헤더가 이긴다** — 24컬럼 탭이면 작성 중단 후 사용자에게 확인한다.

## 화면 ID (F열)

기획서 스펙 페이지 우측 상단의 화면 식별자. 필드명 우선순위 **`Screen ID` → `Page ID` → 기타**.

측정 시점에 **두 구분자 패턴이 혼재**했다 — 정규화되어 있지 않다.

| 패턴 | 예 |
|------|-----|
| `VIOE-NN_NN_NN_NN` (언더스코어 3) | `VIOE-03_01_04_13` |
| `VIOE-NN_NN_NN-NN` (언더스코어 2 + 하이픈) | `VIOE-02_01_01-11` |

패턴 차이는 기획서 원문 표기 차이가 반영된 결과다. **한 시트에 섞여도 정상.**
구분자를 임의로 통일·변환하지 않는다.

예상 결과에서 화면 이동을 서술할 때 목적 화면 ID를 괄호로 인용:
`HPA 스케줄 생성 화면(VIOE-03_01_04_14)으로 이동`

## enum — VIOLA 실측

### 우선순위 분포

**P3 74.9% · P2 13.0% · P4 6.9% · P1 5.1%**

### 구분 분포 — 지배 구분은 **`표시`**

**표시 55.9% · 엣지 14.5% · 인터랙션 11.2% · 부수 6.9% · 정상 6.3% · 비정상 5.1%**

> **`표시` 가 과반(56%)인 것이 이 양식의 지배적 특징이다. `표시` 가 적으면 커버리지 부족 신호.**
> UI 표출을 요소 단위로 잘게 쪼개는 것이 정상 상태다.
> **TROMBONE은 정반대(`정상` 65%)이므로 규칙을 옮겨 쓰지 마라.**

### 구분 × 우선순위 결합 규칙 (실측 근거)

| 구분 | 우선순위 | 강도 |
|------|---------|------|
| `부수` | **항상 `P4`** | 23/23, 예외 0건 |
| `정상` | **`P1` 또는 `P2` 만** | `P3`/`P4` 사례 **0건** |
| `비정상` | `P2` 기본 | P2(13) / P3(4) |
| `표시` / `인터랙션` / `엣지` | `P3` 기본 | **`표시` 에 `P1` 부여 사례 0건** |

`P1` 은 `정상`·`인터랙션` 에만 등장한다. 기준은 비즈니스 임팩트가 아니라
**"이 검증이 깨지면 다음 화면으로 갈 수 없는가"** 다.

> **TROMBONE `정상` 은 P1~P4를 전부 쓴다.** 여기 규칙을 그쪽에 적용하지 마라.

### 3 Depth (K) — 4종 고정

`목록` / `생성` / `수정` / `상세` 중 택일.

- **팝업·모달·다이얼로그 → `상세` 고정**
- `등록`/`검색`/`-` 는 사용 사례 0건 → **신규 도입 금지**

## 표기 컨벤션 — VIOLA 고유

### UI 라벨 = **백틱**

- 사용률: **절차 65% / 예상 결과 52%**
- 감싸는 대상: UI 레이블·버튼명·컬럼명·상태 enum·메시지 원문·형식 문자열
- **대괄호 `[ ]` 는 태그 전용** (비고·피드백). 본문 문체에 쓰지 않는다

> **TROMBONE과 정반대다.** 그쪽은 절차 백틱 0.0%(0/3,953)이고 UI 라벨을 대괄호로 감싼다.

### 절차·예상 결과 실측값

| 지표 | 값 |
|------|-----|
| 절차 평균 단계 수 | **1.01** (최대 2) |
| 절차 1단계 행 비율 | **99.4%** (329/331). 4단계 이상 **0건** |
| 절차 평균 길이 | 24자 |
| 예상 결과 평균 줄 수 | **1.18** (최대 2) |
| 예상 결과 종결 | **명사형 100%** — `~표출`(압도적)·`~이동`·`~정렬`·`~삭제`·`~전환`·`~불가`·`~처리`. 서술형 **0건** |

## VIOLA 암묵 규칙 (프로파일 고유분만)

1. **솔루션은 `VIOLA` 고정** — 모듈 접미사 금지
2. **TC ID `TC_VIO_{3자리}`, 제품 전역 연속, 화면 단위 블록**
3. **`1 Depth` 는 탭당 1개 값**
4. **사전조건 100% 채움** (공란 허용하지 않는다)
5. **`표시` 케이스를 요소 단위로 빠짐없이 쪼갠다** (과반이 정상 상태)
6. **`부수` → 항상 `P4`. `정상` 에 `P3`/`P4` 를 주지 않는다. `표시` 에 `P1` 금지**
7. **UI 레이블·상태값·메시지는 백틱 + 기획서 원문 인용.** 대괄호는 태그 전용
8. **팝업 `3 Depth` 는 `상세` 고정**
9. **`3 Depth` 는 4종만** (`등록`/`검색`/`-` 금지)
