# 작업 디렉터리 재편 + 기획서 이미지 재사용 — 설계

- 날짜: 2026-09-19
- 상태: 설계 확정 (구현 전)
- 후속 스펙: `2026-09-19-prd-digest-design.md` (기획서 분석 절차 신설) — **이 스펙이 먼저다**

## 1. 문제

### 1-1. 작업 디렉터리가 하나뿐이라 제품·판본이 섞인다

모든 절차가 `_workspace/` 한 곳을 쓴다. 다른 제품이나 다른 판본을 작업하려면
기존 것을 `_workspace_prev_{설명}_{날짜}/` 로 **통째로 옮기는 수밖에 없다**
(`testcase-auto` SKILL 0-5).

그 이동의 대가가 실측으로 드러났다.

| 실측 | 값 |
|------|-----|
| `_workspace` 크기 | 495MB — **그중 이미지가 484MB** |
| `_workspace_prev_viola-k8s-run_2026-09-15` | 313MB — **그중 이미지가 296MB** |
| 합계 | 같은 PDF의 같은 이미지가 **약 780MB** |

### 1-2. 매 실행 전량 재변환한다

`pdf_to_images.py` 에 캐시·스킵 로직이 **없다**(`exists`/`skip` 검사 0건).
같은 기획서를 다시 다루면 처음부터 다시 변환한다.

| 실측 | 값 |
|------|-----|
| 변환 속도 | 10페이지 **10.3초** (전체 150 DPI) |
| K8s 181p 전체 세트 | 약 **10분** (전체 + 타일 + DESC 크롭) |
| 색 검출 | 단일 프로세스로 멎어 6개 구간 분할 실행이 필요했다 |

### 1-3. 재사용의 전제는 확인됐다

같은 PDF·같은 옵션이면 **출력이 바이트까지 동일**하다.

| 검증 | 결과 |
|------|------|
| 전체 150 DPI 재변환 (`page_018`·`page_019`) | SHA-256 **일치** |
| DESC 크롭 200 DPI `--tile=auto` 재변환 (`t1`~`t4`) | SHA-256 **일치** |

즉 재사용은 **안전하다.** 남은 문제는 *어디에 두고* *무엇을 근거로 같은 것이라고 판정하는가* 다.

## 2. 설계 결정

### 결정 1 — 제품·버전 단위 작업 디렉터리 + 하위 절차 분리

```
_workspace/
├── VIOLA-K8s_4.0_v1/
│   ├── shared/      이미지 · 색 검출 · 취소선 · 판독 품질 + manifest.json
│   ├── digest/      기획서 분석      (prd-digest, 스펙 2)
│   └── testcase/    테스트 케이스    (testcase-auto)
├── VIOLA-CICD_4.0_v2/
│   └── …
└── augment/         추가 작업        (testcase-augment) — 제품·버전 폴더 **밖**
```

**`shared/` 를 두는 것이 이 구조의 핵심이다.** 이미지와 검출 결과는 두 절차가
같이 쓰는 것이라, `digest/` 안에 두면 테스트 케이스 작업이 남의 디렉터리를
들여다보게 되고 **기획서 분석을 건너뛴 실행에서는 경로가 성립하지 않는다.**

**`augment/` 는 제품·버전 폴더 밖이다** (사용자 확정). 이 절차만 원천이 기획서가
아니라 **구글 시트**라 문서 판본 개념이 없다. 버전 폴더 안에 넣으면 실행할 때마다
*어느 판본 폴더에 넣을지* 를 물어야 하는데, 그 답에 의미가 없다.

`.gitignore` 는 이미 `_workspace/` 를 덮으므로 **변경하지 않는다.**

### 결정 2 — 경로를 문서에 박지 않고 루트를 변수로 둔다

**변수는 둘이다.** 하나로 두면 `shared/` 를 가리킬 방법이 없다.

| 변수 | 값 | 쓰는 절차 |
|------|-----|----------|
| `{WS}` | **절차별 작업 루트** — `_workspace/{디렉터리명}/testcase` · `…/digest` · `_workspace/augment` | 전부 |
| `{SHARED}` | `_workspace/{디렉터리명}/shared` | `testcase-auto` · `prd-digest` |

`{디렉터리명}` 의 형식은 결정 3이 정한다.

`testcase-augment` 는 기획서를 읽지 않으므로 **`{SHARED}` 를 쓰지 않는다.**
그 절차의 `{WS}` 는 `_workspace/augment` 로 **실제 경로는 지금과 같다**(결정 1).
경로가 안 바뀌어도 **표기는 `{WS}` 로 통일한다** — 여기만 하드코딩을 남기면
다음에 이 절차를 옮길 때 또 같은 작업을 하게 되고, 그것이 결정 2가 없애려는 것이다.

현재 `_workspace` 참조 실측:

| 대상 | 출현 수 | 성격 |
|------|--------|------|
| 스킬 SKILL.md 5종 + 참조 4종 | **127** | 에이전트에게 주는 지시 — 동작에 영향 |
| 에이전트 5종 | **24** | 같음 |
| `.claude/formats/common.md` | 2 | 같음 |
| 사용자 문서 6종 | 약 40 | 예시 |
| 스크립트 (`scripts/` = 스킬 번들 심볼릭 링크) | 17 | **docstring 예시 + 기본값 4곳뿐** |
| 회귀 가드 | 2 | 경로가 아니라 **파일명**(`00_screen_index`·`03_rows_s`)을 검사 |

**측정 주의** — `.claude/` 를 통째로 훑으면 610회가 나오는데, 그중 다수가
`.claude/worktrees/augment-impl/`(저장소 전체의 낡은 사본, `.gitignore` 대상)와
`.claude/jobs/` 다. **이 스펙의 대상이 아니다.** 측정할 때 제외한다.

- **스킬·에이전트 본문은 `{WS}/01_prd_analysis_s{NN}.md` 처럼 `{WS}` 표기를 쓴다.**
  기존 `{NN}` 표기와 같은 방식이다
- **에이전트 프롬프트에는 치환된 실제 경로를 준다.** 에이전트가 `{WS}` 를 스스로
  치환하게 하지 않는다 — 치환 실수는 엉뚱한 곳에 쓰고도 성공한 것처럼 보이는
  **조용한 오작동**이 된다
- 근거: 2026-08-25 `관리대상` 컬럼(C) 삽입 때 **11개 파일 78건의 열 문자를
  재매핑**해야 했고, 그때 얻은 결론이 *"열 문자를 공용 문서에 박지 말라"* 였다.
  경로도 같다. 변수로 두면 다음에 구조가 또 바뀌어도 고칠 곳이 한 군데다

**스크립트는 수정하지 않는다.** 전부 이미 `--output-dir` / `--out-dir` 를 받으므로
호출부가 경로를 넘기면 그만이다. 기본값 4곳(`detect_red_regions.py:420`,
`pdf_to_images.py:330·339`, `read_tc_inventory.py:761`)은 **그대로 두고**,
오케스트레이터는 **항상 명시적으로 넘긴다**를 규칙으로 한다.

### 결정 3 — 디렉터리명은 Phase 0 확정값이다 (자동 추출 금지)

형식: `{제품}_{제품버전}_{문서회차}` — 예 `VIOLA-K8s_4.0_v1`

**파일명에서 자동으로 만들지 않는다.** 실측상 두 축이 다르다.

| 기획서 | 파일명의 제품 버전 | Document History 회차 |
|--------|------------------|---------------------|
| `[4.0] VIOLA_화면기획서_v1_260728.pdf` | `4.0` | `v1 / 2026.07.28` |
| `[4.0] VIOLA CICD_화면기획서_v2_260819.pdf` | `4.0` | `v2 / 2026.08.19` |

**문서 회차가 없으면 같은 제품 버전 안에서 판본이 겹친다** — CI/CD 기획서는 실제로
`v1` → `v2` 로 갱신됐고 둘 다 제품 버전은 `4.0` 이다. **제품 버전이 없으면** 다음
릴리스(`5.0`)의 `v1` 과 충돌한다. 셋을 다 써야 유일해진다.

Phase 0 「기본 정보 수집」에서 **확정값 표로 되보여 주고 확인받는다** —
`추정 금지` 원칙 그대로다. 경로에 쓰므로 공백·슬래시는 `-` 로 치환한다.

### 결정 4 — `manifest.json` 이 재사용 판정의 단일 근거다

`shared/` 에 이미지를 만들 때 **전량 성공한 뒤에야** 기록한다.

```json
{
  "source_pdf": "PDF/VIOLA_V4.0/K8s/[4.0] VIOLA_화면기획서_v1_260728.pdf",
  "sha256": "<PDF 내용 해시>",
  "page_count": 181,
  "variants": {
    "full":  { "dpi": 150, "tile": null,   "files": 181 },
    "tiled": { "dpi": 150, "tile": "auto", "files": 377 },
    "desc":  { "dpi": 200, "tile": "auto", "crop": "desc", "files": 733 }
  },
  "created": "2026-09-19T00:00:00+09:00"
}
```

- **`manifest.json` 자체가 완료 마커다.** 없으면 캐시로 인정하지 않는다.
  변환이 중간에 끊긴 디렉터리가 유효한 캐시로 보이면 **페이지가 조용히 빠진다**
- **키는 경로가 아니라 PDF 내용 해시다.** 같은 경로에 `v2` 를 덮어쓰는 일이
  실제로 일어난다(CI/CD 기획서가 `v1` → `v2` 로 갱신됐다)

### 결정 5 — 이미지 재사용은 Phase 0 선택 입력 + 대조 필수

Phase 0 「기획서 경로」 옆에 **(선택) 이미 변환된 이미지 경로**를 받는다.
값이 있으면 1-A 변환을 건너뛴다. 생략하면 지금과 같이 변환한다.

| 상황 | 처리 |
|------|------|
| `manifest.json` 있음 + `sha256` 일치 | **재사용** |
| `manifest.json` 있음 + `sha256` 불일치 | **중단.** 어느 기획서로 만든 이미지인지 알리고 사용자 판단을 받는다 |
| `manifest.json` 없음 | **경고 + 확인.** 페이지 수만 대조하고, 진행하면 그 사실을 산출물에 남긴다 |
| 일부 variant 누락 (예: `desc` 없음) | 그 variant 만 변환해 채운다 |

**불일치를 중단으로 둔 이유** — 다른 판본으로 변환된 이미지를 읽으면
**분석이 낡은 기획서를 보는데 아무도 모른다.** 결과물은 정상으로 보이고
검증도 통과한다. 누락보다 해롭다.

색 검출·취소선 검출·판독 품질 결과도 이미지의 결정적 함수이므로 같은 규칙으로
`shared/` 에서 재사용한다.

### 결정 6 — 재실행 시 `shared/` 는 남긴다

`testcase-auto` SKILL 0-5 를 이렇게 바꾼다.

| 상황 | 처리 |
|------|------|
| 제품·버전 디렉터리 없음 | 초기 실행 |
| 있고 "다시"/"재실행" | `{그 디렉터리}_prev_{설명}_{날짜}/` 로 이동 — **단 `shared/` 는 제자리에 남긴다** |
| 있고 "특정 화면만 보완" | 부분 재실행 (지금과 동일) |
| 있고 변경 없이 다음 단계 | 이어 실행 (지금과 동일) |

`shared/` 를 남기는 것이 1-1에서 본 296MB 중복과 10분 재변환을 없앤다.
**제품·버전이 다르면 애초에 다른 디렉터리이므로 이동 자체가 대부분 사라진다** —
이동은 이제 *같은 제품의 같은 판본을 처음부터 다시 할 때* 만 일어난다.

### 결정 7 — 기존 산출물은 이관하지 않는다

현재 `_workspace/` 와 `_workspace_prev_viola-k8s-run_2026-09-15/` 는 **그대로 둔다.**
완료된 작업의 기록이고, 옮겨서 얻는 것이 없다. 새 구조는 **다음 실행부터** 적용한다.

## 4. 회귀 가드 (`verify_unit_migration.sh` 신설분)

**허용 지점을 한 곳으로 좁히는 것이 가드의 설계다.** `{WS}` 가 실제로 어느 경로인지
적는 곳은 **오케스트레이터 SKILL 2종뿐**이고, 나머지는 `_workspace` 를 아예 쓰지 않는다.

| # | 종류 | 대상 | 내용 |
|---|------|------|------|
| 1 | `present` | 오케스트레이터 SKILL 2종 | `{WS}` 표기가 존재 |
| 2 | `absent` | **에이전트 5종 + 비오케스트레이터 스킬·참조** | `_workspace` 가 **한 번도** 등장하지 않음 |
| 3 | `absent` | 오케스트레이터 SKILL 2종 | 산출물 경로 하드코딩(`_workspace/[0-9]`, `_workspace/pdf_images`) 없음 — 루트 정의만 허용 |
| 4 | `present` | `prd-analyzer` SKILL | manifest 대조 규칙(`manifest.json` + `sha256`) |
| 5 | `present` | `testcase-auto` SKILL | 재실행 시 `shared/` 제외 규칙 |
| 6 | `present` | 에이전트 5종 | **치환된 실제 경로**를 받는다(스스로 치환하지 않는다) |
| 7 | `present` | `testcase-augment` SKILL | `{WS}` = `_workspace/augment` — 제품·버전 폴더 밖 |

**음성 대조 필수** — 각 가드마다 위반을 주입해 FAIL 이 나는지 확인하고 원복한다.
가드가 통과만 확인되면 *패턴이 약해 선언이 사라져도 통과하는* 경우를 놓친다
(2026-09-15 「권위 선언」 가드가 그랬다).

## 5. 하지 않는 것

- **스크립트 기본값 변경** — 호출부가 항상 명시적으로 넘기므로 불필요하고,
  직접 실행하는 사용법 문서를 깨뜨린다
- **기존 `_workspace/`·`_workspace_prev_*` 이관** (결정 7)
- **`.gitignore` 변경** — `_workspace/` 가 이미 덮는다
- **`prd-digest` 신설** — 스펙 2
- **해시 기반 전역 캐시** — 사용자가 경로를 지정하는 방식으로 충분하다.
  전역 캐시는 정리 정책·용량 관리가 따라붙는데 그만한 이득이 없다

## 6. 미해결

- 한 기획서가 **여러 제품에 걸치는 경우**(공용 정의 문서)의 디렉터리 귀속.
  현 실측에는 사례가 없어 규칙을 만들지 않는다 — 나오면 그때 정한다
