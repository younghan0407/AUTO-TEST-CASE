# 처리 단위 재편 — 챕터(간지) → 화면 ID(Screen ID / Page ID) 1개

- 날짜: 2026-09-02
- 상태: 설계 확정 (구현 계획 대기)
- 범위: 스킬 5개 · 에이전트 4개 · 양식 사양 1개 · 사용자 문서 4개 · `CLAUDE.md`

## 1. 배경

현행 하네스는 **간지(챕터 구분 슬라이드)** 로 처리 단위를 잡는다. 2026-06-11에 전체 일괄 처리의 품질 문제(누락 다수)와 처리 시간 과다를 개선하려고 도입한 구조로, 챕터 하나가 페이지 10~15장이다.

이 단위에는 세 가지 어긋남이 있다.

1. **시트의 행 단위와 처리 단위가 다르다.** 시트에서 케이스를 식별하는 축은 `화면 ID` 컬럼인데, 처리·리뷰·산출물은 챕터로 묶여 있어 "이 화면 케이스가 다 나왔는가"를 챕터 단위 산출물에서 역산해야 한다.
2. **정책 예외 항목이 이미 화면 ID 단위다.** 2026-09-02에 도입한 정책 예외는 화면 ID 목록으로 받는데 처리 단위가 챕터여서, 한 챕터 안에 기본 정책 화면과 예외 정책 화면이 섞인 상태로 한 에이전트에게 넘어간다.
3. **간지에 의존하는 단위는 기획서 편집 관행에 종속된다.** 간지가 없는 기획서, 간지 하나에 화면이 20개 이상 몰린 기획서에서 단위가 무너진다.

## 2. 변경 요지

**분석·생성·작성·리뷰의 단위를 화면 ID(`Screen ID` 또는 `Page ID`) 1개로 통일하고, 화면 하나를 시트 작성까지 끝낸 뒤 다음 화면으로 넘어간다.**

| | 현행 | 변경 후 |
|---|---|---|
| 처리 단위 | 챕터(간지) 1개 = 페이지 10~15장 | **화면 ID 1개** = 페이지 1~3장 |
| 단위 결정 | 간지 슬라이드 감지 (1-B) | **화면 식별자 추출 → 화면 인덱스** |
| 루프 | `for 챕터: 분석 → 생성 → 시트 → 리뷰` | `for 화면: 분석 → 생성 → 시트 → 리뷰` |
| 시트 작성 | 챕터당 1회 append | **화면당 1회 append** (Phase 0에서 정한 탭 하나에 순차 누적) |
| 간지 | 처리 단위 | **화면 인덱스의 그룹 라벨로 강등** (분석 컨텍스트로 유지) |

## 3. 확정된 설계 결정

### 결정 1 — 공통 DESC C-ID: Phase 1에 전역 사전 스캔을 둔다

**문제.** 현행 C-ID 배정 규칙은 *"오케스트레이터가 모든 챕터 분석을 받은 뒤 한 번에 배정"* (`common.md` 규칙 5)이다. 이는 2026-08-25 `C5` 충돌 12행 사고의 대책으로, **순차 배정이 그 사고의 직접 원인**이었기 때문에 세운 규칙이다. 그런데 화면 단위 즉시 작성은 정의상 순차 배정이다 — 뒤 화면을 보기 전에 앞 화면 행이 시트에 박힌다. 공통 DESC는 정의상 여러 화면에 걸치는 공유 키이므로 정면 충돌한다.

**해결.** 배정 시점을 루프 **이전**으로 옮긴다. Phase 1-B 화면 인덱스 사전 스캔이 전체 페이지를 얕게 훑으면서 공통 DESC 후보를 함께 잡고 C-ID를 선배정한다. 화면 루프에 진입할 때 C-ID가 이미 확정돼 있으므로 시트 행 소급 수정이 발생하지 않는다.

**기각한 대안.**
- *소급 보정* — 시트 쓰기가 append 전용이 아니게 되고, 보정 누락 시 태그 역추적이 조용히 끊긴다.
- *공통 DESC를 화면 단위로 축소* — 사양 v1.7·v1.8이 확정한 「C-ID = 정의를 잇는 공유 키」 규칙의 철회이며, 한 정의가 여러 화면에 걸칠 때 연결이 사라진다.

### 결정 2 — CH-ID: `CH{NN}-N` 표기 유지, `NN` = 화면 인덱스 순번

태그 문자열 형식과 기존 시트·사양 표기를 그대로 두고 `NN`의 의미만 재정의한다. `SC{NN}-N` 같은 새 접두어는 기존 탭에 이어 쓸 때 한 탭에 두 체계가 섞이고, 화면 ID 원문 접두(`[변경 VIOE-02_01_01-11-3 …]`)는 화면 ID에 하이픈이 있어 항목 번호 경계가 모호해진다.

### 결정 3 — 리뷰: 화면마다 실행, 전역 지표는 Phase 5로 이관

화면 1개의 케이스 표본은 5~20건이다. 프로파일 실측 분포와 대조하는 편차 점검(`testcase-reviewer` §3-1)을 이 표본에서 돌리면 지배 구분 역전이 상시 Critical로 뜬다. 화면 단위 리뷰는 결함을 조기에 잡는 역할만 맡고, 전역 지표는 Phase 5 집계 리뷰에서 1회 측정한다.

### 결정 4 — 화면 ID 없는 페이지: 종류별 분기

| 종류 | 처리 |
|---|---|
| 간지 · 목차 | 인덱스 제외 (UI·Description 없음 = 케이스 원천 없음) |
| 공통 정책 · 플로우 페이지 | `NOID-{일련번호}` 으로 **독립 단위** 등재 |

직전 화면에 병합하지 않는다 — 여러 화면에 걸치는 공통 정책 페이지를 한 화면에만 귀속시키면 나머지 화면에서 근거가 사라진다.

**`NOID` 단위의 표기 규칙:**

- `NOID-{일련번호}` 의 일련번호는 **인덱스 순번과 별개인 자체 연번**이다 (`NOID-01`, `NOID-02`). 인덱스 순번은 다른 화면과 같은 축을 공유한다
- 시트의 `화면 ID` 컬럼에는 **`NOID-01` 을 쓰지 않는다.** 그 값은 기획서에 없는 문자열이므로, 사양의 No-data 규칙에 따라 표기한다. `NOID` 는 하네스 내부 단위 식별자로만 쓴다
- 해당 케이스의 `비고` 에는 근거 페이지를 남겨 역추적을 보장한다 (예: `[DESC p10-2항]`)

### 결정 5 — 첫 화면 검토 게이트 유지

첫 번째 화면은 시트 작성 전에 케이스 목록을 사용자에게 보여주고 확인받는다(현행 "첫 챕터 검토 게이트"의 이관). 문체·태그·enum 오류를 첫 화면에서 잡아야 나머지 전 행에 번지지 않는다. 두 번째 화면부터 자동 진행.

## 4. 새 파이프라인

Phase 0(기본 정보 5개 게이트)과 Phase 1-A(이미지 준비·판독 품질 게이트)·1-D(양식 드리프트 검증)는 변경 없다.

### Phase 1-A-3 — 변경 표시 검출: 전역 1회 실행

챕터별 실행(`_workspace/red_regions/ch{N}`)을 **전역 1회 실행 + 화면별 페이지 슬라이스 전달**로 바꾼다. 출력은 `_workspace/red_regions/` 평면 구조이며, 오케스트레이터가 화면 인덱스의 페이지 범위로 잘라 각 화면 에이전트에게 넘긴다. 화면 수만큼 스크립트를 재실행하는 낭비를 막는다.

`--color=both --no-crops` 로 표시색을 먼저 실측하는 절차는 유지한다.

### Phase 1-B — 화면 인덱스 사전 스캔 (간지 감지 대체)

경량 스캔 에이전트 1개가 전체 페이지를 순서대로 **얕게** 훑는다. 판독 깊이는 화면 식별자 · 페이지 경계 · Description 항목 제목 · 상호 참조 원문(`… 참고`) 수준까지이며, **본 판독은 Phase 2가 한다.** 산출물 3개:

1. `_workspace/00_screen_index.md`
2. `_workspace/00_cid_register.md`
3. 화면 식별자 출처 필드명 (`Screen ID` / `Page ID` / 기타) → 제품 프로파일의 화면 ID 체계와 대조하고 어긋나면 보고

**인덱스 작성 규칙 (경계 케이스):**

| 상황 | 처리 |
|---|---|
| 한 화면 ID가 여러 페이지에 걸침 | 묶어서 **한 단위** |
| 한 페이지에 여러 화면 ID (팝업 등) | 페이지 중복 등재 허용 — 단위 기준은 화면 |
| 같은 화면 ID가 문서 앞뒤로 떨어져 등장 | 한 단위로 병합하고 페이지 목록에 둘 다 기재 |
| 화면 ID 판독 불가 | `[판독 불가]` 로 등재 + 1-C에서 사용자 확인. **추정 금지** |
| 간지 · 목차 | 제외 |
| 공통 정책 · 플로우 페이지 | `NOID-{순번}` 독립 단위 |

### Phase 1-C — 사용자 확인 게이트: 화면 인덱스 확인

챕터 목록 대신 화면 인덱스를 보여주고 확인받는다. **화면 수와 예상 에이전트 사이클(화면 N개 → `3N + 1`회, 마지막 1회는 Phase 5 집계 리뷰)을 함께 알린다** — 챕터 1개(3회)에서 화면 8개(25회)로 늘어나는 것은 사용자가 알고 시작해야 한다.

확정된 인덱스는 `_workspace/00_screen_index.md` 에 저장한다.

### Phase 2~4 — 화면 루프

```
for 화면 in 화면 인덱스:
    Phase 2: 분석  → _workspace/01_prd_analysis_s{NN}.md
    Phase 3: 생성  → _workspace/03_testcases_s{NN}.md
             → 시트 append → 인덱스 상태·행 범위 기록
    Phase 4: 리뷰  → _workspace/04_review_report_s{NN}.md
```

산출물 접미사는 `_s{NN}` 이다. 화면 ID를 파일명에 넣지 않는다 — 하이픈·언더스코어·길이 문제가 있고, 인덱스에 순번↔화면 ID 매핑이 있다.

**Phase 2 (분석)** — `prd-analyst` 에게 넘기는 입력에 화면 ID 원문 · 페이지 범위 · 소속 간지 제목 · 그 화면의 정책(기본 또는 예외) · 색 검출 슬라이스 · 판독 이슈 페이지를 포함한다. Phase 0 확정값 4개(제품 유형 / 기획서 유형 / 예외 항목 / 취소선=삭제 여부) 전달 의무는 유지한다.

**Phase 3 (생성 + 작성)** — 첫 화면만 검토 게이트. 시트 append 후 인덱스에 행 범위를 기록한다.

**Phase 4 (리뷰)** — 화면 단위에서 점검하는 것:

| 점검 | 근거 절 |
|---|---|
| 기획 ↔ 케이스 커버리지 | §2 |
| 양식 준수 (컬럼 · enum · 문체 · 태그) | §3 |
| 컬럼 기재 규율 (열 오배치) | §3-2 |
| 정책 예외 양방향 | §3-3 |
| 시트 ↔ 로컬 일치 | §4 |
| 공통 DESC 누락 · UI↔DESC 불일치 | §5 · §5-1 |
| 변경분 한정 모드 검증 | §5-2 |
| 취소선 삭제 항목 양방향 (정상 케이스 금지 = Critical) | §5-2-1 |
| 변경 범위 초과 (박스는 범위를 확정하지 않는다) | §5-2-2 |
| 판독 이슈 반영 | §5-3 |

**화면 단위에서 제외하는 것:** §3-1 분포 편차 점검, TC ID 연속성. 둘 다 전역 지표다.

### Phase 5 — 합본 + 전체 집계 리뷰 1회 신설

합본은 현행처럼 순번 순으로 합산한다(`01_prd_analysis.md` · `03_testcases.md` · `04_review_report.md`).

**신설 — 전체 집계 리뷰:**

| 항목 | 판정 |
|---|---|
| 분포 편차 (프로파일 실측 대비) | 지배 구분 역전은 Critical |
| TC ID · `No` 연속성 | 중복·결번은 Major |
| C-ID 레지스터 ↔ 시트 태그 대조 | 정의표 없는 C-ID 사용은 Major |
| CH-ID 충돌 0건 | 충돌은 Critical |
| 화면 인덱스 전 항목 상태 = 완료 | 미완료 항목은 누락으로 보고 |

## 5. 신설 산출물 사양

### `_workspace/00_screen_index.md`

`00_chapters.md` 를 대체한다. 진행 상태가 여기 남으므로 **화면 단위 부분 재실행의 기준 파일**이 된다.

```markdown
# 화면 인덱스

- 기획서: PDF/VIOLA_V4.0/03_파드.pdf
- 화면 식별자 출처: Screen ID
- 문서 기본 정책: 변경
- 예외 항목: VIOE-03_01_04_13 (신규 정책)

| 순번 | 화면 ID(원문) | 페이지 | 소속 간지 | 정책 | 상태 | 시트 행 |
|------|--------------|--------|----------|------|------|--------|
| 01 | VIOE-02_01_01-11 | p5~p7 | 통합 모니터링 | 변경 | 완료 | 2~19 |
| 02 | VIOE-02_01_02 | p8 | 통합 모니터링 | 변경 | 완료 | 20~31 |
| 03 | VIOE-03_01_04_13 | p9 | 파드 | **신규(예외)** | 분석중 | - |
| 04 | NOID-01 | p10 | 파드 | 변경 | 대기 | - |
```

- 상태 enum: `대기` / `분석중` / `작성중` / `완료` / `실패`
- `시트 행` 은 append 직후 오케스트레이터가 기록한다. 미작성은 `-`

### `_workspace/00_cid_register.md`

**오케스트레이터 단독 소유(write).** 분석 담당은 읽기 + 발급 요청만 한다.

```markdown
# 공통 DESC C-ID 레지스터

※ 배정 권한은 오케스트레이터에 있다. 분석 담당은 로컬 번호를 매기지 않는다.

| C-ID | 정의 내용 | 근거 화면 ID · DESC 항목 | 적용 화면 순번 | 연결 근거(상호 참조 원문) |
|------|----------|------------------------|--------------|------------------------|
| C1 | '터미널 실행' 버튼 동작 | VIOE-03_01_01-01 > 2항 | 01, 04 | `상세 동작은 목록 > '작업' 버튼 정의와 동일하게 제공 (VIOE-03_01_01-01 > 2항 참고)` |
```

**운용 규칙:**

1. Phase 1-B 사전 스캔이 후보에 `C1`~`Cn` 을 선배정한다
2. 루프 중 새 정의가 발견되면 분석 담당이 **발급을 요청**하고, 오케스트레이터가 다음 번호를 부여하며 레지스터에 정의·근거를 추가한다
3. **현행 "분석 담당이 자기 분석서 기준 `C1` 부터 매긴다" 규칙은 폐지한다** — 챕터 일괄 배정이 사라져 로컬 번호가 무의미해지고, 오히려 2026-08-25 `C5` 충돌의 재발 경로가 된다
4. 정의 일치 판정 근거는 **기획서의 상호 참조**뿐이다 (사양 v1.8 그대로). 일자·회차·내용이 같아도 상호 참조가 없으면 병렬 변경으로 두고 연결하지 않는다
5. 정의표에 없는 C-ID를 시트에 쓰지 않는다

## 9. 신규 에러 처리

| 에러 | 대응 |
|---|---|

| 인덱스에 없는 화면 ID가 분석 중 발견 | 보고 후 인덱스에 추가. **임의로 진행하지 않는다** (인덱스가 진행 상태의 단일 출처이므로 우회하면 상태가 깨진다) |

| 화면 수가 과다 (예: 50개 초과) | 1-C 게이트에서 사이클 수를 알리고 범위 축소 여부를 확인 |

## 11. 검증 방법

기존 실행 산출물을 회귀 기준으로 쓴다.

1. **화면 인덱스 정확성** — `_workspace_prev_021_monitoring_20260827` (VIOLA `02-1`, 챕터 4개)의 기획서로 화면 인덱스를 생성하고, 기존 챕터별 분석서의 화면 ID 목록과 대조해 누락·중복 0건을 확인한다
2. **C-ID 연속성** — 같은 기획서에서 레지스터가 `C1` 을 여러 화면에 공유 배정하는지, 2026-08-25 충돌 패턴(다른 정의에 같은 번호)이 재발하지 않는지 확인한다
3. **CH-ID 충돌** — 챕터 의미 CH-ID가 있는 기존 탭에 append해 최대 `NN` 다음부터 부여되는지 확인한다
4. **취소선 · 색 박스 규칙 회귀** — Boot Factory 기획서(2026-09-02 두 규칙의 근거 실측 대상)로 돌려 삭제 항목 정상 케이스 0건 · 전면 박스 전수화 0건을 확인한다
5. **분포 편차 오탐 소멸** — 화면 단위 리뷰 보고서에 분포 편차 Critical이 뜨지 않고 Phase 5에서만 측정되는지 확인한다
