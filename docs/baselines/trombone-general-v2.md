### 비고 공란 212행의 실제 원인 — V/W 역할 혼동

W열 태그 실측이 원인을 가리킨다.

```
V 태그 상위 : [공통 DESC] 133 · [DESC ❸-N-a] 58 · [DESC ❶-N-a] 39 …
W 태그 상위 : [공통 DESC]  82 · [DESC ❹-N] 24 · [확인 불가] 18 · [기획 확인] 18 · [DESC ❷-N-a] 17 …
```

**V에 써야 할 근거 태그(`[DESC …]`, `[공통 DESC]`)가 W열로 갔다.** 그래서 V가 비었다.
사양의 역할 분리(V=근거 / W=확인사항)를 지키지 못한 것이며, 단순 누락이 아니라 **열 오배치**다.

참고: 팀 작성 `07.일반`에도 같은 혼용이 21행(4%) 있으나 소수 이탈이고,
하네스 출력은 그 비율이 훨씬 높다.

## 원인 분석 — 규칙 공백

분포 편차는 케이스 단위의 실수가 아니라 **정책이 제품 중립이 아니었기 때문**이다.

`testcase-generator` §1의 분류별 권장 개수 표가 **스킬 본문에 하드코딩**돼 있었다.

```
표시 형식 검증  8~15개/화면      ← 이 비율이 VIOLA 양식(표시 56%)에서 나왔다
인터랙션 검증   5~10개/화면
정상 흐름       2~4개/화면
부수적          3~5개/화면
```

TROMBONE 팀 실측은 `정상` 65% / `표시` 2.4%다. **정반대 분포에 VIOLA 정책이 적용됐다.**
출력의 `표시` +29.4%p, `인터랙션` +16.7%p 가 이 표의 직접적 결과다.

3 Depth 세분화도 같은 성격이다 — 사양에 **탭별 실사용 범위**(대부분 모듈은 3종)가 기록돼
있는데 생성 단계가 참조하지 않았다.

## 조치 (2026-08-24 반영)

| 발견 | 조치 |
|------|------|
| 분포 정책이 스킬에 하드코딩 | `testcase-generator` §1을 **사양의 실측 분포 기준**으로 전환. 하드코딩 표는 사양이 없을 때의 폴백으로 격하 |
| 3 Depth 세분화 | 생성 단계에서 **사양의 탭별 실사용 범위**를 따르도록 명시 |
| V/W 역할 혼동 | 근거 태그는 **V열 전용**, 확인사항은 W열 전용임을 생성·리뷰 양쪽에 명시 |
| 비고 공란 | 사양이 `실질 필수`로 표시한 컬럼의 공란을 Critical로 점검 |
| 미사용 컬럼 채움 | 사양이 `미사용`으로 표시한 컬럼의 공란 유지를 생성 단계에 명시 |
| 구분×우선순위 결합 위반 | 사양의 100% 결합 규칙(`표시`→P3, `부수`→P4)을 생성 단계에서 준수 |
| 분포 점검 부재 | `testcase-reviewer`에 **분포 편차 점검** 추가 |
